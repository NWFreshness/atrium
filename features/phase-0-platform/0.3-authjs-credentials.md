# Feature 0.3: Auth.js credentials login

**Phase:** 0 — Atrium platform
**Status:** completed
**Estimated effort:** 4–6 hours
**Depends on:** 0.2
**Blocks:** 0.4, 0.5

## Goal

Only the two env-seeded users can log in. Everyone else hits `/login`. No signup.

## Scope

Include:
- Auth.js (Credentials provider) + JWT session cookie
- `/login` form (email + password)
- Logout
- Unauthenticated requests to `/` (and future app routes) redirect to `/login`
- Authenticated `/login` redirect to `/`
- Generic error: `Invalid email or password`
- Playwright: bad password stays on login; owner credentials reach `/`

Exclude (for now):
- OAuth, magic link, signup, password reset
- Nav strip, theme toggle, launcher cards (0.4)
- Reset demo (0.5)
- Fancy login design (readable and accessible is enough)

## Spec

Session must expose at least: `user.id`, `email`, `tenantId`, `role`.

Credentials authorize by looking up `users.email` and verifying `passwordHash`. Unknown email and wrong password take the same failure path.

## Acceptance criteria

1. [x] Unauthenticated GET `/` redirects to `/login`
2. [x] Wrong password shows `Invalid email or password` and does not set a session
3. [x] Owner email/password signs in and can load `/`
4. [x] Demo email/password signs in and can load `/`
5. [x] Logout returns the browser to `/login` and `/` then redirects again
6. [x] No signup route or “create account” control
7. [x] Playwright spec covers redirect, failed login, and successful login
8. [x] `npm test` and `npm run build` pass

## Implementation notes

- JWT sessions, not database sessions, unless the adapter is already trivial. Keep `accounts` / `sessions` tables in schema even if unused.
- Do not put `tenantId` in query strings or form fields.
- Playwright needs `AUTH_OWNER_EMAIL` / `AUTH_OWNER_PASSWORD` in the e2e env. Document in README. Do not commit real passwords.
- CI: if secrets are missing, skip Playwright or use documented dummy users against a test DB. Do not fail 0.1-style unit CI if e2e is gated — prefer a separate `e2e` job that is allowed to skip without secrets, or run against Neon with GitHub secrets. Pick one and document it in README.
