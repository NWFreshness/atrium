# Feature 0.5: Tenancy helper + Reset demo

**Phase:** 0 — Atrium platform
**Status:** completed
**Estimated effort:** 3–4 hours
**Depends on:** 0.4
**Blocks:** Phase 1 CRM specs/implementation

## Goal

Every server query takes `tenantId` from the session. Demo users can reset their tenant in a transaction. Owner data is unreachable from that path.

## Scope

Include:
- `requireTenant()` (name flexible) that reads the session and returns `{ tenantId, role, userId }` or redirects/throws
- Reset demo server action: `role === demo` only; delete that tenant’s app rows (none yet) then re-run demo seed for users/tenants that should remain
- Nav control “Reset demo” visible only for `role === demo`
- Transaction: failure leaves data as-is
- Tests: owner cannot reset; demo can; helper does not accept a client-supplied tenant id

Exclude (for now):
- Deleting CRM/Space/Rolodex rows (tables do not exist). Hook must be shaped so phase 1 registers `resetCrm(tenantId)` without rewriting the button
- Cron
- Resetting the owner tenant

## Spec

```ts
type TenantContext = {
  userId: string
  tenantId: string
  role: 'owner' | 'demo'
}

// Reset demo
// 1. Resolve session; if role !== 'demo', throw
// 2. BEGIN
// 3. For each registered resetter, reset(tenantId)
// 4. Re-seed demo app data for that tenantId (no-op registry in phase 0)
// 5. COMMIT
```

Phase 0 registry is empty (or only a no-op). The button still runs the action and shows success. Phase 1 adds a CRM resetter.

## Acceptance criteria

1. [x] `requireTenant()` uses the Auth.js session, not arguments from the client
2. [x] Calling the reset action as owner fails and does not mutate rows
3. [x] Calling the reset action as demo succeeds (empty registry is OK)
4. [x] “Reset demo” is in the nav for a demo session and absent for owner
5. [x] Failed transaction does not leave a partial wipe (test with a resetter that throws, if one is injected in tests)
6. [x] `npm test` and `npm run build` pass
7. [x] No CRM/Space/Rolodex tables added here

## Implementation notes

- Registry pattern: `resetters: Array<(tx, tenantId) => Promise<void>>`. Empty in 0.5.
- Do not implement cron.
- Success/failure: banner or text on the page is enough; no toast library required.
