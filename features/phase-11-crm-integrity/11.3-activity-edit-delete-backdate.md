# Feature 11.3: Activity delete + edit + backdate + last-contacted

**Phase:** 11 — CRM integrity, dead-ends, and list/task surface
**Status:** specced
**Estimated effort:** 6–8 hours
**Depends on:** 11.1
**Blocks:** 11.9

This is the merged spec (ideas A2 + B4, gaps G1 + G7 + G8). Former "11.8
activity delete" does not exist as its own file; 11.8 in this phase is Deal

## Goal

Close three dead-ends that share one data model:

- **G1** — no activity delete or edit anywhere.
- **G7** — activities cannot be backdated.
- **G8** — no "last contacted" on a contact.

## Scope

Four jobs, sectioned. Do them in this order; they share `ActivityForm` and
`ActivityTimeline`.

### Include

1. Query-adjacent **actions**: `deleteActivityForSession` /
   `deleteActivityAction` and `updateActivityForSession` /
   `updateActivityAction`, following `lib/crm/deal-actions.ts`'s exact shape.
2. **UI** on `ActivityTimeline`: Edit (dialog, `ActivityForm` prefilled) and
   Delete (native `confirm()`, same as the tables).
3. **`occurredAt` in the form**, defaulting to today, sent on create and edit.
4. **Derived `lastContactedAt`** on the contact **detail** page, computed with
   `compareActivitiesNewestFirst`. Keep it derived. Flag contacts with no
   contact in 30 days.

Plus, in the same change: **truncate the done-checkbox accessible name.**
11.1 Journey E uses the current full-description name. This spec owns the
new truncated name and states that Journey E's locator in
`e2e/crm-activities.spec.ts` changes with it. **This spec does not edit
`11.1-crm-e2e-coverage.md`.**

### Exclude (for now)

- **Any edit/delete control on the dashboard feed or follow-up panels.**
  Dashboard rows at `app/(authenticated)/crm/page.tsx:64-96` stay read-only.
  `components/crm/dashboard-followups.tsx` is not modified. A delete control
  there would be a surprise.
- **Re-parenting.** The edit dialog does not offer Organization / Contact /
  Deal pickers and does not change `contactId` / `dealId`.
- **A `lastContactedAt` column on `contacts`.** Derived only — a stored
  column can drift.
- **A Last-contacted column on the contacts table.** That would share
  `contact-table.tsx` with 11.4 (sorting) without a dependency. 11.3 only
  adds the field on the contact detail page. Table surfacing is a later
  feature (or 11.4 if it chooses to, after 11.3).
- **`/crm/tasks`, follow-ups as a section.** 11.9.
- **Undo / a toast.** Zero `toast` matches under `app/`, `components/`,
  `lib/`. A deleted activity is gone after confirm.
- **Time-of-day.** `type="date"`; value is midnight UTC, same helper as
  `activity-form.tsx:9-15`.
- **The three CRM list tables.** 11.4 owns those files. 11.3 and 11.4 must
  not collide.
- **Deal number validation, detail-page record edit, filters, QuickFind,
  email uniqueness, delete-consequence preview.**

## Spec

### Job 1 — actions

Follow `lib/crm/deal-actions.ts`:

- `*ForSession(getSession, …, repo?: CrmRepository)` with injectable repo.
- Thin `*Action` that `await import("@/auth")` and calls `*ForSession`.

```ts
export async function deleteActivityForSession(
  getSession: GetSession,
  id: string,
  repo?: CrmRepository,
): Promise<Activity | null> {
  const { tenantId } = await requireTenant(getSession);
  return deleteActivity(tenantId, id, repo);
}

export async function updateActivityForSession(
  getSession: GetSession,
  id: string,
  input: UpdateActivityInput & ClientTenantInput,
  repo?: CrmRepository,
): Promise<Activity | null> {
  const { tenantId } = await requireTenant(getSession, input);
  const existing = await getActivity(tenantId, id, repo);
  if (!existing) return null;
  // type / contact / deal checks mirror createActivityForSession
  return updateActivity(tenantId, id, { …sanitized }, repo);
}

export async function deleteActivityAction(id: string): Promise<Activity | null> {
  const { auth } = await import("@/auth");
  return deleteActivityForSession(auth, id);
}

export async function updateActivityAction(
  id: string,
  input: UpdateActivityInput,
): Promise<Activity | null> {
  const { auth } = await import("@/auth");
  return updateActivityForSession(auth, id, input);
}
```

`deleteActivity` is already tenant-scoped (`queries.ts:408-418`) and already
returns `null` for a missing / other-tenant id (`queries.test.ts:1034`). The
action must not invent a second lookup that skips that.

`updateActivityForSession` returns `null` when `getActivity` misses, matching
`toggleActivityDoneForSession` (`activity-actions.ts:110-122`). Do not call
`updateActivity` with another tenant's id guessed from the body.

`toggleActivityDoneForSession` stays. Edit of `done` in the form goes through
`updateActivityAction`; the checkbox on the timeline still goes through
`toggleActivityDoneAction`.

### Job 2 — Edit / Delete UI, and the truncated done name

On each `ActivityTimeline` row (`activity-timeline.tsx:62-86`), add two
buttons in a `crm-row-actions` cluster, after the Done checkbox:

| Control | Visible label | `aria-label` | Behaviour |
| --- | --- | --- | --- |
| Edit | `Edit` | `Edit ${truncateActivityLabel(activity.description)}` | Opens a dialog mounting `ActivityForm` prefilled. |
| Delete | `Delete` | `Delete ${truncateActivityLabel(activity.description)}` | `if (!confirm(\`Delete ${activity.description}?\`)) return;` then `deleteActivityAction(activity.id)` then `router.refresh()`. |

`confirm()` uses the **full** description, matching the tables
(`deal-table.tsx:117` is `confirm(\`Delete ${deal.name}?\`)`). The
aria-label is truncated so a 4k description does not become the accessible
name.

**The new truncated done-checkbox aria-label (owns the 11.1 Journey E change):**

```ts
aria-label={
  activity.done
    ? `Mark ${truncateActivityLabel(activity.description)} not done`
    : `Mark ${truncateActivityLabel(activity.description)} done`
}
```

```ts
// lib/crm/activity-labels.ts
export const ACTIVITY_LABEL_MAX = 40;

export function truncateActivityLabel(value: string): string {
  if (value.length <= ACTIVITY_LABEL_MAX) return value;
  return `${value.slice(0, ACTIVITY_LABEL_MAX)}…`;
}
```

Ellipsis is U+2026 and is appended **only** when `value.length > 40`.

11.1 Journey E currently locates:

```ts
page.getByRole("checkbox", { name: `Mark ${activityText} done`, exact: true })
```

(`11.1-crm-e2e-coverage.md` §8, citing `activity-timeline.tsx:75-79`).

**11.3 updates that locator in `e2e/crm-activities.spec.ts` to:**

```ts
import { truncateActivityLabel } from "@/lib/crm/activity-labels";

page.getByRole("checkbox", {
  name: `Mark ${truncateActivityLabel(activityText)} done`,
  exact: true,
})
```

and the matching `not done` form. For descriptions ≤ 40 characters the
string is unchanged, so a short e2e stamp still matches; the import is
still required so a later long description cannot silently break. **Do not
edit the 11.1 spec file** — 11.1 said this spec must not pre-write the new
name, and 11.3 must not rewrite 11.1 either. The living locator is the
test file 11.1 creates.

The dialog chrome copies `DealForm` (`deal-form.tsx:118-125`):
`role="dialog" aria-modal="true" aria-labelledby={titleId}`. Title is
`Edit activity` when an existing activity is passed. Escape-to-close and
focus restore to the Edit button are in scope (the tables' forms do not
yet do this; 11.5 will add it on record forms — do not wait for 11.5).

### Job 3 — `occurredAt` in the form, default today

`ActivityForm` today (`activity-form.tsx:17-23`) takes only `contactId?` /
`dealId?`. Extend:

```ts
export function ActivityForm({
  contactId,
  dealId,
  activity,
  onClose,
}: {
  contactId?: string;
  dealId?: string;
  activity?: Activity | null;
  onClose?: () => void;
})
```

- **Date field**, second position (after Type), label **`Date`**,
  `id="activity-occurred-at"`, `type="date"`.
- Default on create: today's UTC date, same `YYYY-MM-DD` encoding as
  `deal-form.tsx:32-40` (`toISOString().slice(0, 10)`).
- Default on edit: `activity.occurredAt` via that helper, or today if null.
- Submit sends `occurredAt: inputValueToDate(occurredAt)` — never omit it
  on create, so the action default at `activity-actions.ts:103-104` is a
  backstop, not the user-facing path.
- Inline create on contact/deal detail pages (`ActivityForm dealId={id}` /
  `contactId={id}` with no `activity` / `onClose`) keeps submit label
  **`Add activity`** (`activity-form.tsx:107-109`). Dialog edit uses
  **`Save`**. After a successful edit, call `onClose?.()` after
  `router.refresh()`, matching `deal-form.tsx:110-111`.
- After a successful inline create, also reset the Date field back to
  today (today it resets type/description/dueDate/done at `:47-50`).

Do not add Date to the dashboard.

### Job 4 — derived last contacted on the contact detail page

`app/(authenticated)/crm/contacts/[id]/page.tsx` already loads
`listActivitiesAction({ contactId: id })` (`:27`). After that list:

```ts
import { compareActivitiesNewestFirst } from "@/lib/crm/queries-shared";

const newest = [...activities].sort(compareActivitiesNewestFirst)[0];
const lastContactedAt = newest?.occurredAt ?? null;
const STALE_MS = 30 * 24 * 60 * 60 * 1000;
const stale =
  lastContactedAt === null ||
  Date.now() - lastContactedAt.getTime() > STALE_MS;
```

Add to the existing `<dl>` (`:36-58`), after Organization:

| dt | dd |
| --- | --- |
| `Last contacted` | `formatDate(lastContactedAt)` when present; `Never` when null. If `stale`, also render the exact text **`No contact in 30 days`** in the same `<dd>` (after the date or `Never`). |

`formatDate` already lives in this page's import graph via activities;
import it from `@/lib/crm/format` (`format.ts:8-17`, UTC).

**Do not add a column to `contacts`.** Do not write `lastContactedAt` on
update of an activity. Recompute on every render.

If the contact has activities whose `occurredAt` is null, the comparator
puts them last (`queries-shared.ts:174-179`), so last-contacted uses the
newest dated activity, then falls back to `Never` only when the list is
empty or every `occurredAt` is null.

### Acceptance behaviour (ideas doc bar)

- Delete persists across refresh.
- An edit **re-sorts the timeline correctly when `occurredAt` changes**
  (create two activities, edit the older one's Date to today, reload,
  assert it is first).
- Both actions are tenant-scoped and return `null` for another tenant's id.
- No `deleteActivity` UI on dashboard feed rows.

## Implementation notes

- Query layer is unchanged. `deleteActivity` / `updateActivity` already
  exist (`queries.ts:394-418`).
- Prefill the form from `activity.type`, `description`, `occurredAt`,
  `dueDate`, `done`. Do not send `contactId`/`dealId` on edit.
- `ActivityForm` used inline (no `activity`) must not render dialog chrome;
  dialog chrome is the timeline's wrapper, or a mode flag. Preferred: the
  timeline wraps the form in the existing `.crm-dialog-backdrop` /
  `.crm-dialog` classes from `org.module.css`, same as `OrgTable`
  (`org-table.tsx:120-122`) wrapping `OrgForm` which *does* include chrome.
  Then `ActivityForm` in dialog mode should include the same chrome
  `OrgForm` does, gated on `activity != null || onClose != null`. Inline
  create on detail pages stays a bare `<form>` as today.
- CSS stays `crm-` prefixed. No Tailwind.
