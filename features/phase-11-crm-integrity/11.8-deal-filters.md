## Spec

1. **Opts.**

   ```ts
   export type ListDealsOpts = {
     q?: string;
     organizationId?: string;
     contactId?: string;
     stage?: DealStage;
     closeBefore?: Date;
     closeAfter?: Date;
   };
   ```

2. **Predicates** (AND with existing ones; all optional):

   - `stage` → `deals.stage = stage`
   - `closeAfter` → `deals.closeDate IS NOT NULL AND deals.closeDate >= closeAfter`
   - `closeBefore` → `deals.closeDate IS NOT NULL AND deals.closeDate <= closeBefore`

   A deal with `closeDate: null` (`lib/crm/schema.ts:81` is nullable) does not
   match a close-date window. Inclusive bounds. Date-only URL values are
   interpreted as UTC date-only, consistent with `utcDateOnly` in
   `lib/crm/dashboard.ts:86-88` (`toISOString().slice(0, 10)`).

3. **Unknown / garbage URL values are ignored, not 500s.** Copy
   `parseStatus` (`contacts/page.tsx:8-19`):

   ```ts
   function parseStage(raw: string | string[] | undefined): DealStage | undefined {
     const value = Array.isArray(raw) ? raw[0] : raw;
     if (typeof value === "string" && (DEAL_STAGES as readonly string[]).includes(value)) {
       return value as DealStage;
     }
     return undefined;
   }
   ```

   `parseCloseDate`: missing, `""`, or `Invalid Date` → `undefined`. Never
   throw. Never `notFound()`.

4. **GET form** on `/crm/deals`, same toolbar pattern as contacts:

   - Search `q` — already there (`deals/page.tsx:31-33`).
   - `<select id="deal-stage-filter" name="stage">` labelled "Stage", first
     option `All` with `value=""`, then `DEAL_STAGES` (`lib/crm/constants.ts:1-8`:
     New, Qualified, Proposal, Negotiation, Won, Lost).
   - `<input id="deal-close-after" name="closeAfter" type="date">` labelled
     "Close after".
   - `<input id="deal-close-before" name="closeBefore" type="date">` labelled
     "Close before".
   - `<select id="deal-org-filter" name="organizationId">` labelled
     "Organization", `All` + the page's organizations. `contactId` stays
     available to the contact detail caller
     (`app/(authenticated)/crm/contacts/[id]/page.tsx:26`) and does not need a
     deals-page select.

   `method="get"` `action="/crm/deals"`. Empty fields omit the filter (browser
   still sends `stage=` — parse treats `""` as undefined). Submit button stays
   "Search".

5. **Composition.** `?q=widget&stage=Negotiation&closeAfter=2026-01-01` applies
   all three. Reloading the URL restores the controls via `defaultValue` /
   `defaultValue={stage ?? ""}` the way contacts do at `:53`.

6. **Callers.** `listDeals(tenantId, repo)` and `listDealsAction()` remain
   valid. Pipeline is unfiltered. Organization detail still passes
   `{ organizationId: id }`. Contact detail still passes `{ contactId: id }`.

## Recorded limits

1. **No Playwright in this feature.** URL round-trip is proven by the parser
   unit + the page wiring; a browser test can land in 11.2's deals e2e later.
2. **`contactId` is not a deals-page control.** It already works from the
   contact detail page. Adding a second people select is noise.
3. **Timezone.** URL dates are UTC date-only strings. A closeDate stored at
   `23:00Z` the previous local evening may fall on a different calendar day
   than the user's clock. Same convention as the dashboard. Not revisited here.
4. **Pipeline is unfiltered on purpose.** Stage is already the column.
5. **B5 bounded lists is still deferred.** Filters reduce the set; they do not
   paginate it.
