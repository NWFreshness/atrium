# Feature 11.10: CRM QuickFind

**Phase:** 11 — CRM integrity, dead-ends, and list/task surface
**Status:** specced
**Estimated effort:** 5–7 hours
**Depends on:** nothing
**Blocks:** nothing

## Goal

From any CRM section, `⌘K` / `Ctrl+K` jumps to an organization, contact, deal,
or activity. Closes **G16 / B1**. **No new route** — the palette is mounted in
the CRM layout (11.9's `/crm/tasks` is the only Phase 11 route).

## Scope

### Include

- `lib/crm/search.ts` — `searchAll(tenantId, q, repo?)` → typed buckets
  `{ organizations, contacts, deals, activities }`, each capped (~5) with a
  total count.
- `lib/crm/search-actions.ts` — `"use server"`; `tenantId` from
  `requireTenant` only.
- Client component modelled on `quick-find.tsx`, mounted so the shortcut
  works from all five CRM sections and from `/crm/tasks` once 11.9 exists
  (layout already wraps every CRM page: `app/(authenticated)/crm/layout.tsx:5-10`).
- Activity results link to the activity's contact or deal; no contact and no
  deal → no broken link.
- Acceptance includes **the client-boundary gate still passes.**

### Exclude (for now)

- A `/crm/search` route or replacing the per-page `?q=` boxes.
- Searching Groove, Space, Rolodex, or users.
- Fuzzy ranking beyond case-insensitive `includes` on the same fields the
  list pages already search (plus activity `description`).
- A command palette of actions (create org, etc.). Results are records.
- Changing `lib/space/search.ts`.

## Spec

1. **`searchAll(tenantId, q, repo?)`.**

   - Trim `q`. Empty / whitespace → empty buckets, totals 0, no repo calls
     required.
   - `requireTenantId(tenantId)` — never read tenant from `q`.
   - Needle: `q.trim().toLowerCase()`.
   - Buckets, each `{ hits: T[]; total: number }` with `hits.length <= 5`:

     | bucket | match fields (same as list search where it exists) | href |
     | --- | --- | --- |
     | organizations | name, website, industry (`organizationMatchesSearch`) | `/crm/organizations/{id}` |
     | contacts | name, email, jobTitle (`contactMatchesSearch`) | `/crm/contacts/{id}` |
     | deals | name, org name, contact name (`dealMatchesSearch`) | `/crm/deals/{id}` |
     | activities | `description` (no list-page `q` today) | see §3 |

   - `total` is the un-capped match count. `hits` are the first 5 after a
     stable sort (name/description asc, then id).
   - All four lists are tenant-scoped via the existing `listX` helpers.
   - Cap is 5 per bucket, not 5 total.

2. **Client component** (`CrmQuickFind`), interaction copied from
   `components/space/quick-find.tsx:31-74`:

   - Window listener: `key.toLowerCase() === "k"` and (`metaKey` or
     `ctrlKey`) → `preventDefault()` → open.
   - Open: focus the input. Empty query shows no hits (placeholder
     `Search CRM`). Debounce 150 ms then `searchCrmAction(q)`.
   - Groups in order Organizations, Contacts, Deals, Activities. A group with
     `total === 0` is omitted. Group label includes total when `total > 5`
     (`Organizations · 12`).
   - Arrow keys move highlight across the flattened visible hits; Enter
     navigates; Escape closes. Clicking a hit navigates and closes.
   - Trigger button visible in the chrome, `aria-label` `Search CRM`,
     showing `⌘K` or `Ctrl+K` via the same `shortcutLabel()` test
     (`quick-find.tsx:15-20`).
   - Overlay: `role="dialog"` `aria-modal="true"` `aria-label="Search CRM"`.
     CSS under `.crm-quick-find*` in a module imported only by this
     component. No Tailwind, no shadcn.

3. **Activity href.** If `contactId`, `/crm/contacts/{contactId}`. Else if
   `dealId`, `/crm/deals/{dealId}`. Else **omit the hit from the activity
   bucket** *or* render it as non-interactive text in the palette — pick
   omit (simpler, no broken link). Record the choice in the test. Never
   `href="#"`.

4. **Client boundary (acceptance, not a footnote).**

   `components/crm/crm-quick-find.tsx` may:

   - value-import `searchCrmAction` from `lib/crm/search-actions.ts`
     (`"use server"` is a walk stop at `client-boundary.test.ts`);
   - `import type` hits/results from `lib/crm/search.ts` or `queries-shared`.

   It may **not**:

   - `import { searchAll } from "@/lib/crm/search"` if `search.ts`
     value-imports `queries.ts`;
   - `import { listContacts } from "@/lib/crm/queries"`;
   - `import { type Contact, listContacts } from ...` (one value binding
     poisons the clause — `client-boundary.test.ts:186-187`).

   **Acceptance includes: `lib/client-boundary.test.ts` still passes.**
   Prove the gate still bites: a one-line value-import of `queries.ts` from
   the client component must fail the test; reverse it.

5. **`?q=` unchanged.** Submitting the organizations/contacts/deals search
   forms still filters those tables. QuickFind does not write `?q=`.

6. **Shortcut from every CRM section.** Because it is mounted in the CRM
   layout/subnav, it works on Dashboard, Organizations, Contacts, Deals,
   Pipeline, and on `/crm/tasks` once that route exists. This feature does
   **not** depend on 11.9; it must not wait for the sixth tab.

## Acceptance criteria

1. [ ] `⌘K` / `Ctrl+K` opens the palette from any of the five current CRM
       sections (and from `/crm/tasks` if present).
2. [ ] Results are grouped in four buckets, each capped at 5 with a total
       count.
3. [ ] Each organization/contact/deal hit links to its detail route.
4. [ ] An activity result links to its contact or deal, or is omitted; **no
       broken link**.
5. [ ] Results are tenant-scoped (a second tenant's rows never appear).
6. [ ] The `?q=` page filters keep working unchanged.
7. [ ] **`lib/client-boundary.test.ts` still passes.** A planted
       value-import of `lib/crm/queries.ts` from the client component turns
       it red; that plant is reverted byte-identically.
8. [ ] Empty query does not hit the database (or returns immediately with
       empty buckets).
9. [ ] `env -u DATABASE_URL npm test` and
       `AUTH_SECRET=ci-build-placeholder npm run build` pass.

## Recorded limits

1. **No Playwright in this feature.** Shortcut + dialog is unit/source
   tested; a browser journey can join a later e2e pass. Space QuickFind also
   shipped without a Playwright file.
2. **Activities without a contact and without a deal are omitted** from
   results (Spec §3). They remain on the dashboard feed.
3. **Cap is 5/bucket, not relevance ranking.** Good enough at current seed
   sizes; B5 pagination is a different problem.
4. **Does not search notes on organizations** (`organizations.notes`) or
   deal stage strings. Match fields are the list-page fields plus activity
   description.
5. **No route.** Do not add `/crm/search` to the design-doc Routes list.
6. **Layout mount vs subnav sibling** is an implementer choice inside Spec
   §Files to modify. Either is in scope; a second mount is not.
