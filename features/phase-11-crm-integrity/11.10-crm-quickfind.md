# Feature 11.10: CRM QuickFind

**Phase:** 11 — CRM integrity, dead-ends, and list/task surface
**Status:** specced
**Estimated effort:** 5–7 hours
**Depends on:** 11.9 (`/crm/tasks` must exist, or the acceptance criterion "⌘K opens from any CRM section" freezes a five-section list)
**Blocks:** none

## Goal

A signed-in CRM user can type a fragment of anything — a person, a company, a
deal, a note they logged — and jump to it from any CRM section, with one
`⌘`/`Ctrl+K`.

Today there is no cross-entity jump at all: three separate `q` boxes, one per
list page, each searching three fields of one table and none of them searching
activities. `"app/(authenticated)/crm/organizations/page.tsx":25-30`,
`"app/(authenticated)/crm/contacts/page.tsx":44-62`, and
`"app/(authenticated)/crm/deals/page.tsx":31-36` each render one
`<input name="q">` scoped to their own table. The dashboard
(`"app/(authenticated)/crm/page.tsx"`) and the pipeline
(`"app/(authenticated)/crm/pipeline/page.tsx":1-5`) have none. Gap **G16**.

Space 2.7 already ships this exact interaction
(`components/space/quick-find.tsx` + `lib/space/search.ts` +
`lib/space/search-actions.ts`). CRM copies the **interaction**, not the file: the
CRM needs four buckets, not Space's one flat list of pages.

## Scope

Include:

- **One pure helper**, `lib/crm/search.ts`, exporting `searchCrm(tenantId, q,
  repo?)` → `CrmSearchResults`. Types come from `lib/crm/queries-shared.ts` via
  `import type`, which `lib/client-boundary.test.ts:189-211` erases at build
  time and therefore permits.
- **One server action module**, `lib/crm/search-actions.ts` (`"use server"`),
  exporting `searchCrmForSession(getSession, q, repo?)` and
  `searchCrmAction(q)`. `tenantId` comes from `requireTenant`
  (`lib/tenancy/index.ts:27-43`) and from nowhere else. The action's
  `…ForSession` twin takes `repo` last so the memory repo can be injected in
  vitest, exactly as `lib/space/search-actions.ts:7-14` does.
- **Four buckets**, in subnav order: Organizations, Contacts, Deals,
  Activities. Each capped at **5** returned hits, with the **total** match count
  carried separately so the client can say "and 3 more".
- **A client component**, `components/crm/quick-find.tsx` (`"use client"`), plus
  `components/crm/quick-find.module.css` with `crm-`-prefixed classes. Mounted
  in the CRM layout so ⌘K works from all six sections, and its trigger placed
  inside the existing `atrium-subnav` row (a sibling of the `<ul>`, **not** an
  `<li>` in it).
- **Keyboard:** `⌘K`/`Ctrl+K` opens; `↓`/`↑` move the active option and wrap;
  `Enter` navigates; `Escape` closes and returns focus to the trigger; `Tab` and
  `Shift+Tab` are `preventDefault()`ed so focus cannot leave an open modal.
- **ARIA:** combobox pattern via `aria-activedescendant` — DOM focus stays in the
  input, the active option is a property of the input, and
  `aria-activedescendant` is **absent** when there is no active option.
  `role="group"` + `aria-labelledby` per bucket so four buckets are legal inside
  one `role="listbox"`. A `role="status"` region announces the result count.
  `aria-busy` on the listbox while a search is in flight.
- **`⌘K` is ignored while any `role="dialog" aria-modal="true"` is open.**
- Unlinked activities (no `contactId` **and** no `dealId`) are **excluded** from
  the palette. A listbox option that does nothing on Enter is a broken listbox.

Exclude (for now):

- **Search inside activity descriptions' full text beyond a substring match** —
  this feature matches `activities.description` as one field, nothing more.
- **Bounded lists or pagination on the list helpers.** 11.10 caps **its own**
  results per bucket; `listOrganizations` / `listContacts` / `listDeals` /
  `listActivities` stay unbounded (B5 is a phase non-goal). Do not add a
  `searchOrganizations` list helper — extend nothing, call nothing new: the
  helper re-uses the four existing `listX(tenantId, repo, opts)` entry points.
- **Any change to the three `?q=` page filters.** They keep working exactly as
  they are. The palette is a second entry point, not a replacement. No
  `?quickfind=` param, no shared URL state with the page filters.
- **Changing the pipeline board, the dashboard, or the tables** — 11.8 and 11.4
  own those. No list row gets a QuickFind affordance.
- **A second modifier.** `Meta` **or** `Control`, one of them, never both
  required. Chromium-only coverage (`playwright.config.ts:18`).
- **A "recent" or "frequently visited" mode.** An empty query shows
  `Type to search`, as Space does.
- **A `cmd`-palette for the whole Atrium app.** Space already binds
  Meta/Ctrl-K (`components/space/quick-find.tsx:31-43`) and is mounted only in
  the Space shell (`components/space/space-shell.tsx:21`); the CRM mounts its own
  in `"app/(authenticated)/crm/layout.tsx"`. The two are never mounted at once,
  so there is no conflict to mediate. Do **not** lift either into a global
  provider.
- **A second search field in the CRM nav, or a `?q=` in the palette's own
  result rows.** Rows navigate; they do not re-filter.
- **Replacing, editing or refactoring the three existing record forms' `titleId`
  constants** (`components/crm/org-form.tsx:40`, `contact-form.tsx:47`,
  `deal-form.tsx:81`). 11.5 owns the Escape/focus work on those forms. 11.10
  only needs to *not fight* them — see the ⌘K-while-modal rule in §3.
- **Any client value-import of `lib/crm/queries.ts`, `schema.ts`, `lib/db`,
  `drizzle-orm`, or `@neondatabase/serverless`.** Type-only imports of the
  barrel stay legal (`lib/client-boundary.test.ts:184-186`); the design names
  `queries-shared.ts` for this feature's types.

## Spec

### 0. Types and module shape

`lib/crm/search.ts` exports exactly these:

```ts
import { formatMoney } from "./format";
import {
  listActivities,
  listContacts,
  listDeals,
  listOrganizations,
} from "./queries";
import {
  requireTenantId,
  type Activity,
  type Contact,
  type CrmRepository,
  type Deal,
  type Organization,
} from "./queries-shared";

export type CrmSearchBucket = "organization" | "contact" | "deal" | "activity";

export type CrmSearchHit = {
  /** Bucket discriminator. */
  bucket: CrmSearchBucket;
  /** The row's primary key. */
  id: string;
  /** What the option shows as its name. */
  label: string;
  /** One dim line under the label. Never null: the client renders it. */
  detail: string;
  /** Where Enter goes. Always a CRM route, always absolute. */
  href: string;
};

export type CrmSearchResults = {
  organizations: CrmSearchHit[];
  contacts: CrmSearchHit[];
  deals: CrmSearchHit[];
  activities: CrmSearchHit[];
  /** Total matches per bucket, **before** the cap. Drives "and N more". */
  totals: Record<CrmSearchBucket, number>;
};

export const CRM_SEARCH_LIMIT = 5;

export async function searchCrm(
  tenantId: string,
  q: string,
  repo?: CrmRepository,
): Promise<CrmSearchResults>;
```

Rules:

- `tenantId` first, then `q`, then optional `repo` — the established positional
  order (`lib/crm/queries.ts:100-110`, `lib/space/search.ts:27-31`).
- **Throws** on a missing or blank `tenantId` via `requireTenantId`
  (`lib/crm/queries-shared.ts:84-89`), which the barrel itself calls first on
  every list path (`lib/crm/queries.ts:105`, `:181`, `:257`, `:350`).
  `searchCrm` therefore calls `requireTenantId` before it touches a store, so
  the throw happens even if a caller passes a repo.
- Blank or whitespace-only `q` returns four **empty arrays** and four **zero**
  totals. Not `null`, not a recent list. `lib/space/search.ts:33-36` returns
  `[]` for an empty query; the same rule, widened to buckets.
- The `Activity` / `Contact` / `Deal` / `Organization` / `CrmRepository` imports
  are **`import type`**. Dropping one `type` keyword makes
  `lib/client-boundary.test.ts` fail, naming this file. That is the whole point
  of the module split and the reason `lib/rolodex/circle-stats.ts:1-13` exists.

`lib/crm/search-actions.ts` mirrors `lib/space/search-actions.ts:1-19` exactly:

```ts
"use server";

import { requireTenant, type GetSession } from "../tenancy";
import type { CrmRepository } from "./queries-shared";
import { searchCrm, type CrmSearchResults } from "./search";

export async function searchCrmForSession(
  getSession: GetSession,
  q: string,
  repo?: CrmRepository,
): Promise<CrmSearchResults> {
  const { tenantId } = await requireTenant(getSession);
  return searchCrm(tenantId, q, repo);
}

export async function searchCrmAction(q: string): Promise<CrmSearchResults> {
  const { auth } = await import("@/auth");
  return searchCrmForSession(auth, q);
}
```

`requireTenant`'s second parameter is the client-supplied object it must
**ignore** (`lib/tenancy/index.ts:27-31`; every CRM action passes its input
there anyway, e.g. `lib/crm/deal-actions.ts:61`). The palette sends no
`tenantId` at all. There is no `ClientTenantInput` on this action because
`searchCrmAction`'s parameter is a bare string, which is the strongest possible
version of "never take tenant id from the request body or query string".

### 1. What each bucket matches, and what it links to

Re-use the search predicates that already exist. Do not write new ones, and do
not write a fourth list helper.

| Bucket | Predicate | Source of truth | `label` | `detail` | `href` |
| --- | --- | --- | --- | --- | --- |
| Organizations | `organizationMatchesSearch` | `lib/crm/queries-shared.ts:108-120` (name / website / industry) | `row.name` | `row.industry ?? ""` | `/crm/organizations/${row.id}` |
| Contacts | `contactMatchesSearch` | `lib/crm/queries-shared.ts:122-131` (name / email / jobTitle) | `row.name` | `row.email ?? row.jobTitle ?? ""` | `/crm/contacts/${row.id}` |
| Deals | `dealMatchesSearch` | `lib/crm/queries-shared.ts:133-166` (name, **plus** the linked org's and contact's names) | `row.name` | `` `${row.stage} · ${formatMoney(row.value)}` `` | `/crm/deals/${row.id}` |
| Activities | `row.description.toLowerCase().includes(needle)` — **plus** the unlinked exclusion in §2 | no predicate exists; write a three-line local one, do not export it | `truncate(row.description, 60)` | `` `${row.type} · ${parentName}` `` | the parent's detail route, §1.1 |

`dealMatchesSearch(row, repo, q)` takes the **repository** as its second
argument (`lib/crm/queries-shared.ts:133-137`) because it resolves
`organizationId` / `contactId` against sibling rows. Under Drizzle the linked
names come from the left joins in `listDealsInDrizzle`
(`lib/crm/queries-drizzle.ts:279-293`) and the predicate is never called; the
memory path is what calls it. Passing `repo` is therefore **required** for the
memory path and harmless for Drizzle. When `repo` is undefined and the store is
Drizzle, call the predicate with a synthetic empty repository so the
organization/contact branches are inert — the SQL has already filtered.

`formatMoney` is `lib/crm/format.ts:1-6` and is client-safe (no imports). Deal
`detail` therefore renders `$1,000.00` in the palette. That is a deliberate
difference from the drag e2e, which asserts `25%` instead of money strings
because a `formatMoney` change would break it; here the money *is* the
discriminator between two deals of the same name.

**1.1 — an activity's `href` is its parent, never itself.** There is no
`/crm/activities/[id]` route. `lib/crm/schema.ts:100-103` makes both
`contactId` and `dealId` nullable `onDelete: "set null"`, so an activity can
have either, both, or neither.

- `dealId` set → `href = /crm/deals/${row.dealId}` and `parentName` is that
  **deal's** name.
- `dealId` null and `contactId` set → `href = /crm/contacts/${row.contactId}`,
  `parentName` is that **contact's** name.
- both null → the hit is **dropped** (§2).

`parentName` is resolved from the rows the helper already fetched, not by a
`getDeal` / `getContact` per hit: one extra query per hit on a keystroke is the
failure mode this spec exists to avoid. Build a `Map<id, name>` for contacts and
for deals from the same fetched arrays, and if a parent id is somehow absent
from the map, fall back to the bare id string as `parentName` rather than
dropping the hit. The nav must still be correct.

### 2. The three rules that are easy to get wrong

**2.1 `escapeIlike` is mandatory, and it is applied in the store, not here.**
`searchCrm` passes the raw trimmed `q` down to `listX(tenantId, repo, { q })`.
The Drizzle store builds the pattern through `containsPattern` →
`escapeIlike` and pairs it with `ESCAPE '\'`
(`lib/crm/queries-drizzle.ts:40-57`), so `%`, `_` and `\` are already literals
on the SQL path. The memory path has **no** escaping —
`organizationMatchesSearch` calls `String.includes` directly
(`lib/crm/queries-shared.ts:117-119`) — and `includes` treats `%` and `_` as
literals already. So a query of `%` returns nothing on both paths, correctly,
for different reasons. `searchCrm` must **not** add its own escaping: a second
`escapeIlike` would double-escape on the SQL path and turn `\` into `\\`.

**2.2 The cap is applied after the predicate, per bucket, and `totals` counts
before the cap.** `CRM_SEARCH_LIMIT = 5`. The memory path filters, counts, then
slices. The Drizzle path is the same shape. Assert in `lib/crm/search.test.ts`:
seven matching organizations return five `organizations` and
`totals.organization === 7`.

**2.3 Unlinked activities are excluded, and the bucket disappears rather than
emptying.** An activity with `contactId === null && dealId === null` is dropped
at the filter stage, **not** the render stage, so it cannot be counted in
`totals.activity` either. If every activity hit is unlinked, the Activities
bucket is **absent** from the listbox — not present and empty. The cost is
real and is recorded in Recorded limits: such an activity is unreachable from
anywhere in the app. `lib/crm/seed.ts:214-225` creates exactly one such row
(`Intro call scheduled for next week.`, contact only — so it is **not** an
orphan; it has `contactId: priya.id`). Do not write a test that asserts the
demo tenant has an orphan.

**Ordering within a bucket**, so the palette is stable across keystrokes:
`label` ascending, then `id` ascending, comparing with `<` / `>` and not
`localeCompare`, mirroring `compareTitleThenId` in `lib/space/search.ts:20-25`.
Bucket order is fixed: organizations, contacts, deals, activities —
the subnav order (`components/crm/crm-subnav.tsx:24-81`) with activities last
because it has no tab.

### 3. The client component

`components/crm/quick-find.tsx`, `"use client"`, one exported component
`CrmQuickFind`. Copy Space's state machine; replace its DOM.

State: `open`, `query`, `results`, `highlighted`, `pending`, and a
`triggerRef` for focus restoration. `useId()` for the three ids below — the
repo's own forms use a hardcoded `titleId` constant
(`components/crm/org-form.tsx:40`), which is exactly the pattern the design
ruled out for new dialogs.

**Shortcut.** One `useEffect` window `keydown` listener, the Space shape
(`components/space/quick-find.tsx:31-43`): `event.key.toLowerCase() === "k" &&
(event.metaKey || event.ctrlKey)` → `preventDefault()` → open. It is added
once with an empty dependency array and removed on unmount.

**The modal guard, in this order, before the `preventDefault()`:**

```ts
if (document.querySelector('[role="dialog"][aria-modal="true"]')) {
  return;
}
```

A record form (`components/crm/org-form.tsx:70-75`,
`contact-form.tsx`, `deal-form.tsx:80-85`) and the palette would otherwise be
two stacked overlays sharing one Escape key. This is the interaction 11.10
creates, and it is why the CRM's own dialogs need an Escape handler — **which
11.5 adds**. 11.10 does not add it and does not block on it: with the guard, a
⌘K over a form is a no-op, and the form's missing Escape is 11.5's recorded
work, not a defect 11.10 introduces.

**Debounce: 150 ms, Space's value** (`components/space/quick-find.tsx:63-69`),
with the `cancelled` flag and `clearTimeout` cleanup copied exactly. A
superseded response must not land: a stale result set is a correctness bug in a
palette, not a cosmetic one.

**Markup, exactly.** The ids are `useId()`-derived constants computed once per
mount, so the same id appears in both places that need it:

```
dialog  role="dialog" aria-modal="true" aria-labelledby={titleId}
input   role="combobox"
        aria-expanded="true"
        aria-controls={listboxId}
        aria-autocomplete="list"
        aria-activedescendant={activeId ?? undefined}   ← attribute ABSENT when no active option
        aria-describedby={statusId}
status  <p id={statusId} role="status">…</p>
list    <ul id={listboxId} role="listbox" aria-label="Search results" aria-busy={pending}>
group   <li role="group" aria-labelledby={groupHeadingId}>   ← per non-empty bucket
        <div id={groupHeadingId}>Organizations</div>
option  <li role="option" id={optionId} aria-selected={…}>  ← ONE <li>, role on itself
```

Five deviations from Space's markup, each for a stated reason, each in the
design's ruling:

1. `role="option"` is on the `<li>` itself. Space puts a `role="option"`
   `<button>` **inside** an un-roled `<li>` inside `role="listbox"`
   (`components/space/quick-find.tsx:161-185`); a listbox may only contain
   options or groups, so that intermediate `<li>` is invalid. A group's
   children are the options; that is legal.
2. `aria-activedescendant` is present and correct. Space moves only a
   `highlighted` number and never moves DOM focus
   (`components/space/quick-find.tsx:97-108`); a screen reader in forms mode
   announces the input, not the row. `aria-activedescendant` is the combobox
   pattern and the reason it exists.
3. `aria-activedescendant` is **omitted entirely** when there is no active
   option. An id pointing at nothing is worse than no attribute.
4. `role="status"` announces the count. Space's `<p>No results</p>`
   (`:159`) is a plain paragraph and is never announced.
5. `Escape` returns focus to the trigger. Space's `close()` (`:76-81`) does not,
   which leaves a keyboard user at the top of the document.

`aria-busy={pending}` on the listbox. No spinner: 150 ms does not justify one,
and the debounce already cancels most keystrokes before they fire.

**Key handling** on the dialog's `onKeyDown`, in this order:

- `Escape` → `preventDefault()`, close, `triggerRef.current?.focus()`.
- `Tab` (with or without shift) → `preventDefault()` and nothing else. The
  options are not tabbable under `aria-activedescendant`, so the input is the
  only tabbable thing inside; the trap is this one `preventDefault()`, and it
  is what `aria-modal="true"` promises.
- `ArrowDown` / `ArrowUp` → `preventDefault()`, move `highlighted` and **wrap**
  (`(i + 1) % n` and `i <= 0 ? n - 1 : i - 1`, Space's `:97-108`).
- `Enter` → `preventDefault()` **only if there is an active hit**
  (`if (hit)`); with none, do nothing and let the default happen. A listbox
  with no options must not navigate.

Escape and the arrow keys call `preventDefault()` so the browser does not
scroll the dialog or move focus behind it.

**Navigation.** `router.push(hit.href)` then `close()`. Space's order
(`components/space/quick-find.tsx:83-86`) is `router.push` then `close`; keep
it. The e2e asserts the URL after the navigation settles.

**Rendered states**, and only these:

| State | What renders |
| --- | --- |
| closed | trigger only |
| open, empty query | `Type to search` |
| searching | `aria-busy="true"`, previous list still on screen, no visual change |
| results | groups, options, `role="status"` count |
| no results | `No matches for "<query>"` and a second line `Try a name, company, or deal.` No listbox. |
| action threw | the same no-results state. An error the user cannot act on must not look different from an empty result. |

Wrap the action call in `try`/`catch`; on catch, set results to four empty
buckets with zero totals. Do not surface a mechanism name
(`I12` / UX cross-surface invariant): no `unique`, no `index`, no `23505`, no
table names in any palette string.

**The `role="status"` text**, written once per settled result set, never per
keystroke:

- no query → `Type to search`
- results → `` `${n} organizations, ${m} contacts` `` style: only the buckets
  that are non-empty, joined with `, `, singular for 1. When a bucket is
  truncated, append `, 3 more organizations` naming the **overflow**, so the
  number is honest and not a lie by omission.
- nothing → `No matches`

**The trigger.** A `<button type="button">` with visible label `Search` (Space's
own word, `components/space/quick-find.tsx:132`) and a `<kbd>` chip rendering
`⌘K` on Mac / `Ctrl+K` elsewhere, from `shortcutLabel()`
(`components/space/quick-find.tsx:15-20` — the `navigator.platform` test is
deprecated but it is the shipped precedent, and matching it means one helper, not
two). `aria-keyshortcuts="Meta+K Control+K"`, verbatim from Space (`:130`). The
wrapper is `<div role="search">` inside the `<nav>`, pushed right with
`margin-left: auto`. **The trigger is not brass** (`--ink-dim` text, `--bg-2`
fill, `--line-strong` border; hover → `--ink` on `--bg-3`; `<kbd>` in
`--font-mono` `--text-data` `--ink-faint`), with a 2px `--brass`
`:focus-visible` ring — which `crm-pnw.test.ts:201-209` exempts, since that gate
*requires* the brass ring.

### 4. The CSS module

`components/crm/quick-find.module.css`. Copy Space's declarations **by value**

### 6. Overflow rows — deliberately deferred, and why

Space's palette has one flat list and no overflow affordance. Four buckets with
a cap of 5 each means up to 20 options plus per-bucket "and N more" text. The
design's ruling is that the **count lives in the `role="status"` region and on
the group label** — no `See all` option rows.

A `See all organizations` row that navigates to
`/crm/organizations?q=<query>` would be a *new kind of listbox option*: it does
not match the query, it is not a record, and pressing Enter on it leaves the
palette for a filtered list. That is a "nice extra control", and per the
writing guide a nice extra control is a spec defect. The three list pages that
could receive that `?q=` already have a `q` box; the user who wants to page
through everything types in it.

**The Activities bucket has no list page to overflow to** — there is no
`/crm/activities`, and 11.9's `/crm/tasks` is not text-filterable by the
ruling for this feature. So an activities overflow is unreachable *by
construction*, which is a further reason not to ship three overflow rows that
work and a fourth that does not.

If a later feature wants overflow links, it adds them with the route that makes
them work.

## Implementation notes

- **The client-boundary gate is the whole reason this feature is its own
  feature.** `lib/client-boundary.test.ts:155-166` forbids a **value** import of
  `lib/db`, `lib/{crm,space,rolodex}/{queries,schema,seed,reset}`,
  `drizzle-orm`, or `@neondatabase/serverless` from anything under
  `components/` — and it follows the graph transitively
  (`:310-369`), stopping only at a module whose first statement is
  `"use server"` (`:329-332`). So:
  - `components/crm/quick-find.tsx` → `lib/crm/search-actions.ts` is a **stop**.
    Anything the action value-imports is invisible to the walk, because Next
    replaces that import with an RPC stub.
  - `components/crm/quick-find.tsx` → `lib/crm/search.ts` is **not** a stop.
    `search.ts` value-imports the barrel, so a value import of `search.ts` from
    the component pulls Drizzle into the browser chunk. The component must
    import **only** `search-actions` and **only types** from `search`.
  - `FORBIDDEN` matches `queries-shared` as a path too — the regex is
    `lib/(?:crm|space|rolodex)/(?:queries|schema|seed|reset)\b` with a `\b`,
    and `queries-shared` matches at the `-`. So `import type … from
    "./queries-shared"` is legal **only** because `typeOnlyClause`
    (`:189-211`) erases it. Drop the `type` keyword and the gate fails. That is
    the trap 8.3 paid for in `lib/rolodex/person-fields.ts`; the fix it produced
    is `lib/rolodex/circle-stats.ts:1-13`, and this file is that same shape for
    the CRM.
- **Do not import types from `@/lib/crm/queries` in the new component.** It is
  legal today (`client-boundary.test.ts:184-186`) and
  `components/crm/activity-timeline.tsx:8` does it. The design names
  `queries-shared.ts` for this feature, and the reason is structural: the barrel
  re-exports the same types (`lib/crm/queries.ts:72-89`) but is one `export … from`
  away from becoming a value import. Take the types from `queries-shared`, which
  has no such ambiguity.
- **Two stores, one helper, no third list function.** `searchCrm` calls the four
  existing `listX(tenantId, repo, opts)` entry points. Do not add
  `searchOrganizations`, and do not add a `LIMIT` to any of them — B5 is a phase
  non-goal and 11.8 extends `ListDealsOpts` for its own reasons. The cap lives
  in `search.ts`.
- **The memory repo proves policy, not SQL.** `env -u DATABASE_URL npm test`
  runs `createMemoryCrmRepository()` and the predicates in
  `lib/crm/queries-shared.ts`; `lib/crm/queries-drizzle.ts` is unexecuted. The
  ILIKE `ESCAPE '\'` path (`lib/crm/queries-drizzle.ts:44-57`) and the deals
  left-join search (`:279-293`) are proven only by the Playwright journeys.
- **`dealMatchesSearch` needs the repo; `repo` may be undefined under
  Drizzle.** This is the one genuinely awkward seam in the design. Read
  `lib/crm/queries-shared.ts:133-166`: the second argument is used only to
  resolve `organizationId` and `contactId` to names. Under Drizzle the names
  were already matched in SQL by the left joins, so the JS predicate is never
  consulted. Pass a synthetic `{ organizations: [], contacts: [], deals: [],
  activities: [] }` when `repo` is undefined, and comment why. Do **not** change
  the predicate's signature — it is shared with `listDealsInMemory`
  (`lib/crm/queries-memory.ts`), and 11.8 will lean on it.
- **`getByRole` is a substring match.** `getByRole("link", { name: "Deals" })`
  also matches a deal row's link. The palette's own e2e hits
  `getByRole("dialog", { name: "Search CRM" })` and option text, so the exposure
  is small — but `getByRole("option")` names are record names, and a record
  named `"… Search CRM …"` would collide. Use `{ exact: true }` on every role
  query with a name, and prefer `toHaveText`/`toContainText` over role names for
  option assertions.
- **30 s is the whole-test budget, not the per-assertion budget.** Use
  `test.setTimeout(60_000)` and `NAV_TIMEOUT = { timeout: 20_000 }` on
  post-navigation assertions (`e2e/workroom.spec.ts:205-212` is the precedent for
  both). Never `waitForTimeout` to wait for a result set — the palette's own
  `aria-busy` and the `role="status"` text are the honest synchronisation, and
  the debounce means a fixed sleep either races or wastes 150 ms × n.
- **`retries: 1` on CI** (`playwright.config.ts:13`) hides a flake. Watch the
  retry count on the six-section walk; a palette that only opens on five of six
  routes is a bug, not a flake.
- **`fullyParallel: false` is deliberate** (`playwright.config.ts:11`): one
  worker, one demo tenant. The QuickFind is read-only, so it adds no contention
  — but it must not assume it is the only thing on the page.
- **Local Playwright needs `AUTH_SECRET` in the process env.** `.env` has none
  (controller-measured). `playwright.config.ts:3-7` loads `.env` for the runner
  but the `webServer` inherits the runner's environment, so
  `AUTH_SECRET=local-playwright-secret npx playwright test` is the working
  invocation. And `reuseExistingServer: true` locally (`:31`) means a foreign
  `next-server` on `:3000` silently hijacks the run — kill it by PID, never
  `pkill -f next-server`.
- **The ⌘K-while-modal guard is a query, not a state.** No CRM dialog
  participates in React state the palette can see; the record forms are
  conditionally rendered in table components
  (`components/crm/contact-table.tsx:143-149`,
  `components/crm/deal-table.tsx`). A `document.querySelector` guard is the only
  implementation that works across all of them without a context provider, and
  a provider is out of scope (new state library, I15). Say this in a comment —
  the next reader will otherwise "fix" it with a prop.
- **11.9 lands first, and that is a real dependency, not a formality.** The
  acceptance criterion is "⌘K opens from any CRM section"; there are five
  sections today (`components/crm/crm-subnav.tsx:24-81`) and six after
  `/crm/tasks`. Building 11.10 first freezes a list that 11.9 then falsifies,
  and the e2e's six-section walk would be written against a route that does not
  exist. The layout mount is unaffected either way.
- **What the recorded drift rules say about the trigger.** No brass at rest
  (V7/I6); the 2px `--brass` focus ring is exempt and already required by
  `crm-pnw.test.ts:201-209`. Sentence case, no trailing period on labels.
  `Search` and `⌘K` are Space's own strings — reusing them is the point, and
  changing either is a needless copy divergence.

## Recorded limits

What this feature does **not** prove, stated so a green run is not over-read.

1. **CI does not prove this feature.** Job `ci`
   (`.github/workflows/ci.yml:8-25`) runs `npm test` (vitest, **memory** repo,
   no Postgres, no Playwright) and `npm run build`
   (`AUTH_SECRET: ci-build-placeholder`). Job `e2e` (`:27-66`) runs Playwright
   only if `:46` is true — six secrets after 11.1, including the demo pair.
   A green `e2e` job still needs a reader to confirm `ready=true` and a
   non-zero Playwright count in the log. Whether GitHub actually holds those six
   secrets is **unverified from this repo**; command: the last `e2e` job log's
   `ready=` line, and `gh api …/branches/main/protection`.
2. **No Drizzle SQL is executed in vitest.** The ILIKE `ESCAPE '\'` path
   (`lib/crm/queries-drizzle.ts:44-57`), the deals left-join search
   (`:279-293`), and the un-bounded list queries are proven only by the
   Playwright journeys against dev Neon. A unit test that passes with
   `escapeIlike` deleted from the SQL is not evidence.
3. **Screen-reader behaviour is unverified.** `aria-activedescendant`,
   `role="group"`, and `role="status"` are the correct combobox pattern, and the
   e2e asserts the attributes are present, consistent and non-dangling. Whether
   NVDA announces them *usefully* is a manual pass this feature does not
   perform — the design records the same limit on the UX side.
4. **Focus trapping is one `preventDefault()`, not a trap library.** With
   `aria-activedescendant` the options are not tabbable, so the input is the
   only tabbable thing inside and the rule is sufficient. It is not a general
   focus trap, and it does not cover a future dialog inside the palette.
5. **Unlinked activities are unreachable, and this feature makes that
   permanent-ish.** Dropping them (§2.3) is right — a listbox option that does
   nothing on Enter is broken — but an activity with no contact and no deal is
   now unreachable from the palette as well as from the timeline. Both FKs are
   nullable `onDelete: "set null"` (`lib/crm/schema.ts:100-103`); this is a
   pre-existing shape the phase does not fix, and there is no orphans page.
6. **The `role="status"` announcement is a count, not a summary.** A user with
   20 matches hears "12 organizations, 3 contacts, 5 more deals" and must read
   the list. Whether that is the right amount of speech is a review question,
   not a test.
7. **The 150 ms debounce is unmeasured for the CRM.** Space's value is copied
   as a precedent, not as a measurement on CRM data. A tenant with thousands of
   activities may feel it. What would verify: a timing pass on dev Neon with
   realistic row counts. Bounded lists are the phase non-goal that would fix it
   properly.
8. **No visual regression coverage.** The palette adds a new surface with no
   golden. `tests/theme-contrast.test.ts` proves its *tokens* are legible in both
   themes; it does not prove the composition. Screenshot baselines stay
   deferred for the phase.
9. **Chromium only** (`playwright.config.ts:18`). Safari's
   `navigator.platform` string is what `shortcutLabel()`'s Mac test reads
   (`components/space/quick-find.tsx:15-20`); Firefox and WebKit behaviour of
   `aria-activedescendant` and the `Ctrl+K` default-action `preventDefault()` is
   unproven. Not in scope for this phase.
10. **History claims are unverified.** This spec was written from the working
    tree without running git. Nothing here asserts what a file "used to" do;
    check with `git show main:<path>` before relying on such a claim.

## Controller notes

Writer D, features 11.10 and the controlled port of 11.1. Seven findings, each
with what I did about it. Nothing below silently changed another writer's
feature.

1. **The design names `lib/crm/search.ts` but the same decision requires
   `requireTenantId`, which lives in `queries-shared.ts` — and `search.ts` is
   not on the client side of the boundary.** The value import of
   `./queries-shared` for `requireTenantId` is legal from `lib/`, because
   `lib/client-boundary.test.ts:297-308` seeds its walk at every file under
   `components/` (`:316`) and only *follows* from there. `lib/crm/search.ts` is
   reached only through `search-actions.ts`, which is a `"use server"` stop.
   I stated the import block explicitly in §0 so the implementer does not
   "fix" `requireTenantId` into a local duplicate. If a reviewer wants
   `search.ts` reachable from a client component later, that is a different
   module and this design is wrong for it.

2. **`dealMatchesSearch(row, repo, q)` needs a repository
   (`lib/crm/queries-shared.ts:133-137`) and `repo` is optional.** Under
   Drizzle the names were already matched in SQL by the left joins
   (`lib/crm/queries-drizzle.ts:279-293`), so the JS predicate is never called
   there; under memory it is the whole filter
   (`lib/crm/queries-memory.ts:214`). I specified passing a synthetic empty
   repository when `repo` is undefined, with the reason, rather than changing
   the predicate's signature — 11.8 leans on the same helper. This seam is real
   and the design doc did not name it. Flagging it for 11.8's writer.

3. **`escapeIlike` needs no call in `search.ts`, and calling it would be a
   bug.** The Drizzle store already escapes through `containsPattern` +
   `ESCAPE '\'` (`lib/crm/queries-drizzle.ts:40-57`); the memory path uses
   `String.includes`, which treats `%` and `_` as literals already. A second
   `escapeIlike` double-escapes on the SQL path. Specified as §2.1 with the
   reasoning, because the design's Abuse-and-limits line ("QuickFind must
   `escapeIlike`") reads as an instruction to call it here and is, for this
   seam, the opposite of correct. **The design doc line is satisfied by
   re-using the store's own escaping, which is the stronger claim.**

4. **The UX spec's "See all …" overflow rows are cut, and §6 says why.** Four
   `See all` options inside `role="listbox"` would be options that do not match
   the query and do not navigate to a record; the Activities one has no route
   that can accept `?q=` at all (`/crm/tasks` is not text-filterable by the
   design's ruling). Per the writing guide a "nice extra control" is a spec
   defect, so the overflow count lives in the `role="status"` text and the group
   label instead. If the controller wants the overflow rows, that is a scope
   addition and it needs 11.9's route to be filterable first.

5. **The ⌘K-while-modal guard makes 11.10 depend on 11.5's Escape work, but I
   did not make it a blocking dependency.** With the guard in place
   (`document.querySelector('[role="dialog"][aria-modal="true"]')`), ⌘K over a
   record form is a no-op and the palette is coherent. The record forms still
   have no Escape handler (`components/crm/org-form.tsx:69-76`,
   `contact-form.tsx:78-84`, `deal-form.tsx:118-124` — all three verified, no
   `onKeyDown` anywhere), which is 11.5's work. 11.10 does not add it and does
   not block on it; §3 states both. The UX spec made this a hard prerequisite;
   the design doc's ruling ("⌘K ignored while a modal is open") does not
   require the converse, so I followed the design.
