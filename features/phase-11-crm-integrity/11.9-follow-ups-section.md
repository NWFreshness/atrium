# Feature 11.9: Follow-ups as a real section

**Phase:** 11 — CRM integrity, dead-ends, and list/task surface
**Status:** specced
**Estimated effort:** 6–8 hours
**Depends on:** 11.3
**Blocks:** nothing

The one Phase 11 feature that adds a subnav tab. **Name the blast radius
honestly** (ideas doc B3): this touches the files that *claim* to own the
five-tab shell, the workroom link-walk, and `e2e/crm.spec.ts`'s subnav walk.

## Goal

Give the CRM one list of everything still owed, grouped by when it is due, so
a `dueDate` is a surface rather than a field. Closes **G6 / B3**. Route and
tab label are **`/crm/tasks` / `Tasks`**.

## Spec

1. **Aggregation** (`lib/crm/tasks.ts`), date-only UTC like
   `followUps` (`dashboard.ts:196`):

   Windows, in this order:

   | key | predicate vs `todayKey = utcDateOnly(today)` |
   | --- | --- |
   | overdue | due < today |
   | today | due === today |
   | next7 | today < due ≤ today+7 days |
   | later | due > today+7 days |

   Input: undone activities with a non-null `dueDate` (same filter as
   `dashboard.ts:198`). Sort inside each window by dueDate asc, then id.

   `overdueLabel(due, today)`: `"overdue by 1 day"` / `"overdue by N days"`
   for overdue items; omit on the other windows.

   Keep `dashboard.ts`'s `followUps` working. The dashboard can keep calling
   it (two buckets) or derive overdue/upcoming from the new helper. Either
   way, `DashboardFollowUps` still renders two panels. Do not break
   `lib/crm/dashboard.test.ts`'s `describe("followUps")`.

2. **`ListActivitiesOpts`.**

   ```ts
   export type ListActivitiesOpts = {
     contactId?: string;
     dealId?: string;
     done?: boolean;
     dueBefore?: Date;
     dueAfter?: Date;
   };
   ```

   `done: false` plus `dueAfter`/`dueBefore` is how `/crm/tasks` loads. Do
   not add `listActivitiesByDue`. Extend `listActivities`. Forward through
   `listActivitiesForSession`.

3. **Route `/crm/tasks`.** Server component. `atrium-pagetitle` + `atrium-sub`
   ("What you still owe"). Four `<section>`s in window order, each with an
   `<h2>` (Overdue / Today / Next 7 days / Later), a count, and either the
   list or that window's empty string:

   - Overdue: `No overdue tasks`
   - Today: `Nothing due today`
   - Next 7 days: `Nothing due in the next 7 days`
   - Later: `Nothing due later`

   Each row: description, due date, overdue label when applicable, contact
   link and/or deal link, done checkbox (`aria-label` `Mark {description} done`,
   same pattern as `dashboard-followups.tsx:47-51`). Toggling done calls
   `toggleActivityDoneAction` (already shipped) and `router.refresh()`; the
   row disappears because the query is `done: false`.

4. **Links without breakage.** If `contactId` is set, link
   `/crm/contacts/{contactId}` with accessible name `Contact`. If `dealId` is
   set, link `/crm/deals/{dealId}` with accessible name `Deal`. If neither,
   render the description with **no** `<a href="#">` and no empty `href`.

5. **Dashboard.** Each of the two `DashboardFollowUps` headings gets a
   `See all` link to `/crm/tasks` (accessible name `See all tasks`). Rows
   gain the same contact/deal link rule as §4. Empty copy stays
   `No overdue follow-ups` / `No upcoming follow-ups`.

6. **Subnav.** Sixth entry after Pipeline. Icon: inline SVG in the same
   `icon(...)` helper (`crm-subnav.tsx:8-22`), a simple checklist shape, 24
   viewBox, stroke 1.5. `isCrmSection` unchanged.

   | `lib/crm/nav.test.ts` | Pin `/crm/tasks`. |
