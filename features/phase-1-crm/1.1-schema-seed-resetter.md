# Feature 1.1: CRM schema, seed, and demo resetter

**Phase:** 1 — CRM
**Status:** pending

## Goal

CRM tables exist, every query is tenant-scoped from the session, demo data can be seeded and wiped without touching the owner tenant.

## Scope

Include:
- Drizzle tables: organizations, contacts, deals, activities — each with `tenantId`
- UUID text ids (match users/tenants), not SQLite integers
- Enums/constants: deal stages, contact statuses, activity types, `STAGE_PROBABILITY`, `expectedValue`
- Query helpers that take `tenantId` as a required argument (never from the client)
- Demo seed for the demo tenant only; owner tenant stays empty
- `registerDemoResetter` that deletes that tenant’s CRM rows then re-seeds demo
- Unit tests without `DATABASE_URL` (injected repo / in-memory), including owner isolation and thrown-resetter rollback via existing `runInTransaction` injection

Exclude (for now):
- CRM UI (1.2+)
- TanStack, charts, drag-and-drop
- Space / Rolodex tables
- Switching the app off neon-http globally (resetter uses the 0.5 registry + injected tx in tests)

## Spec

Postgres field shapes (camelCase, like existing schema):

```ts
// organizations: id, tenantId, name, website, industry, notes, createdAt
// contacts: id, tenantId, name, email, phone, jobTitle, organizationId, status, createdAt
// deals: id, tenantId, name, organizationId, contactId, stage, value, probability, closeDate, boardOrder, createdAt
// activities: id, tenantId, type, contactId, dealId, description, occurredAt, dueDate, done, createdAt

// FKs to org/contact/deal: onDelete set null (Bench). tenantId → tenants.id restrict.
// Queries: list/get/create/update/delete each type WHERE tenantId = ?
// Delete org does not cascade-delete contacts/deals (SET NULL).
```

`STAGE_PROBABILITY`: New 10, Qualified 25, Proposal 50, Negotiation 75, Won 100, Lost 0.
`expectedValue(deal) = (value * probability) / 100`.

Demo seed: several orgs, contacts, deals across multiple stages, some activities. Deterministic names (port Bench seed intent, not SQLite ids). Owner seed: none.

## Acceptance criteria

1. [ ] Four CRM tables in Drizzle + a generated migration; every row has `tenantId`
2. [ ] Query helpers refuse to run without `tenantId`; tests prove a second tenant cannot read/write the first tenant’s rows
3. [ ] Demo seed populates only the demo tenant; owner tenant has zero CRM rows after seed
4. [ ] CRM resetter deletes that tenant’s CRM rows then re-seeds demo; owner tenant unchanged
5. [ ] `expectedValue` and stage probabilities match Bench constants
6. [ ] No CRM UI beyond existing Coming soon
7. [ ] `npm test` and `npm run build` pass without `DATABASE_URL` for unit tests
8. [ ] No regressions in 0.5 tenancy tests
