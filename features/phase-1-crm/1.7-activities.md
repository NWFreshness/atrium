# Feature 1.7: Activities and follow-ups

**Phase:** 1 — CRM
**Status:** pending
**Estimated effort:** 4–5 hours
**Depends on:** 1.4, 1.5
**Blocks:** 1.8

## Goal

From a contact or deal, users log a note, call, or email. Optional due date + done flag makes it a follow-up task. Timelines show newest first.

## Scope

Include:
- Add activity from contact detail and deal detail
- Types: note, call, email
- Timeline on contact and deal, newest first (`occurredAt` desc)
- Optional `dueDate`; `done` boolean
- Toggle done persists
- Tenant-scoped actions + unit tests for create and toggle

Exclude (for now):
- Dashboard feed (1.8)
- Email/calendar integrations
- Editing description beyond what’s needed to toggle done (full edit optional, not required)

## Files to create

- `components/crm/activity-form.tsx`
- `components/crm/activity-timeline.tsx`
- `lib/crm/activity-actions.ts`
- `lib/crm/activity-*.test.ts`

## Files to modify

- Contact detail page
- Deal detail page

## Spec

An activity may have `contactId` and/or `dealId`. Description required.

## Acceptance criteria

1. [ ] Add note/call/email from contact detail; it appears on that timeline, newest first
2. [ ] Same from deal detail
3. [ ] Due date + done/not-done persist across refresh
4. [ ] Unit tests for add and toggle completion, tenant-scoped
5. [ ] `npm test` and `npm run build` pass
6. [ ] No regressions in 1.4–1.5

## Implementation notes

- `done` is boolean in the app; store as boolean in Postgres (not SQLite 0/1).
- Icons for note/call/email can be inline SVG; no extra icon pack required.
