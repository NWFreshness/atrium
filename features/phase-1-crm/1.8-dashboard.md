# Feature 1.8: CRM dashboard

**Phase:** 1 — CRM
**Status:** pending
**Estimated effort:** 5–6 hours
**Depends on:** 1.6, 1.7
**Blocks:** 1.9

## Goal

`/crm` is an at-a-glance dashboard whose figures match the underlying tenant data.

## Scope

Include:
- Dashboard as `/crm` landing
- Tiles: open deals, pipeline value, expected revenue, deals won (trailing 6 months), revenue won (trailing 6 months)
- Charts via `recharts` with `isAnimationActive={false}`
- Aggregations in `lib/crm/` functions (unit-tested), not inside chart components
- Recent activity feed
- Upcoming and overdue follow-ups (dueDate set, not done; overdue = dueDate < today)
- Pipeline visualization including expected revenue (funnel and/or win-loss as in Bench IMPLEMENTATION)
- Tenant-scoped: demo sees demo numbers; owner sees only owner data

Exclude (for now):
- Extra analytics, custom date ranges, export
- Chart animation
- Pixel-identical Bench CSS; one color meaning across tiles is enough (document the mapping)

## Spec

Follow Bench `docs/crm/IMPLEMENTATION.md` dashboard section for formulas:
- Expected revenue = value × probability / 100
- Open = not Won/Lost
- Won-per-month / revenue-won use trailing slice, not future-dated wins
- Funnel is cumulative value at or past each stage; Lost omitted; wins capped at trailing six months

## Acceptance criteria

1. [ ] Dashboard shows tiles, charts, recent activity, upcoming/overdue tasks
2. [ ] Figures match unit-tested aggregations on the same dataset
3. [ ] After marking a deal Won or adding an activity/due-dated task, refresh shows the change
4. [ ] Owner and demo dashboards do not mix rows
5. [ ] `npm test` and `npm run build` pass
6. [ ] No regressions in 1.6–1.7

## Implementation notes

- Bench turned chart animation off so screenshots are deterministic. Do the same.
- Purple = deal counts, blue = open pipeline, amber = forecast, green = won, red = lost/late — if using tones.
- Do not put aggregation math in the React tree.
