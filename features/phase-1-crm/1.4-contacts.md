# Feature 1.4: Contacts table and detail

**Phase:** 1 — CRM
**Status:** pending
**Estimated effort:** 4–5 hours
**Depends on:** 1.3
**Blocks:** 1.5, 1.7

## Goal

Users can add, search, filter, edit, and delete contacts. A contact belongs to an organization. Detail shows the org link.

## Scope

Include:
- Contacts table (TanStack Table)
- Search by name and email (job title too, matching Bench)
- Status filter: lead / qualified / customer
- Add / edit / delete; optional `organizationId`
- Detail `/crm/contacts/[id]` with org name/link; activity timeline is 1.7
- Organization detail lists that org’s contacts
- Tenant-scoped server actions + unit tests

Exclude (for now):
- Separate “leads” list (status=lead is enough)
- Activities
- Pagination / import

## Files to create

- `app/(authenticated)/crm/contacts/[id]/page.tsx`
- `components/crm/contact-table.tsx`
- `components/crm/contact-form.tsx`
- `lib/crm/contact-actions.ts`
- `lib/crm/contact-*.test.ts` as needed

## Files to modify

- `app/(authenticated)/crm/contacts/page.tsx`
- `app/(authenticated)/crm/organizations/[id]/page.tsx` — list contacts

## Spec

Statuses: `lead | qualified | customer`. No other values.

## Acceptance criteria

1. [ ] Contacts table lists this tenant’s contacts
2. [ ] Add, edit, delete persist across refresh
3. [ ] Search by name and email; status filter shows only that status
4. [ ] Contact detail shows its organization (if set)
5. [ ] Organization detail lists its contacts
6. [ ] Tenant isolation tests pass
7. [ ] `npm test` and `npm run build` pass
8. [ ] No regressions in 1.3

## Implementation notes

- A “lead” is a contact with status lead — no second entity.
- Org select on the form lists this tenant’s organizations only.
