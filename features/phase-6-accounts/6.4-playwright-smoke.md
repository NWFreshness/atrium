# Feature 6.4: Accounts Playwright smoke

**Phase:** 6 — Accounts
**Status:** specced
**Estimated effort:** 2–4 hours
**Depends on:** 6.2, 6.3
**Blocks:** nothing

## Goal

Prove signup, closed-flag behaviour, change-password, and that owner/demo/Reset demo are untouched.

## Scope

Include:

- `e2e/accounts.spec.ts` (or `e2e/signup.spec.ts`)
- Open-signup journey (flag on)
- Change-password journey for that member
- Member does not see Reset demo
- Owner and demo still log in; existing login spec still passes
- Closed-flag coverage: if the running server has the flag off, assert closed UI and skip create; the helper closed-path is already unit-tested in 6.1

Exclude (for now):

- OAuth click-through
- Visual screenshot diffs
- Deleting the member tenant afterward (use a unique email per run)

## Files to create

- `e2e/accounts.spec.ts`

## Files to modify

- `playwright.config.ts` — only if the webServer env must pass `AUTH_SIGNUP_ENABLED=true` for the open journey. Document it. Do not write secrets.
- `.env.example` — comment that e2e open-signup needs the flag on

## Spec

1. Unique email per run (`e2e.accounts.<timestamp>@atrium.local`). Password ≥ 12 chars, not the owner/demo passwords.
2. Flag on: `/login` → Create an account → fill signup → land `/` → no Reset demo button → CRM/Space empty of demo seed names used in existing smokes (spot-check: demo org “Northwind” absent, or simply that Reset demo is absent and launcher is visible).
3. Same member: identity link → `/settings` → change password → logout → login with the **new** password reaches `/`. Old password fails with the generic login error.
4. Owner login still reaches `/`. Demo login still reaches `/` and still sees Reset demo.
5. Unauthenticated `/settings` → `/login`. Unauthenticated `/` still → `/login`.
6. `{ exact: true }` on nav labels. Do not add Settings to the 5.7 top-nav walk list.
7. `next build` typechecks `e2e/`, so run the build after editing the spec. Playwright `expect` timeout goes on the matcher, not the `expect()` second argument.

The suite cannot flip the flag mid-run (one Next process). Open-signup tests `test.skip` unless `AUTH_SIGNUP_ENABLED === "true"`. Closed UI can be asserted when the flag is not `true`. Unit tests already cover `signUp` throwing `closed`.

## Acceptance criteria

1. [ ] Member signup (flag on) reaches `/` with no Reset demo
2. [ ] Member change-password then login with the new password succeeds
3. [ ] Owner and demo login specs still pass; demo still has Reset demo
4. [ ] Unauthenticated `/settings` redirects to login
5. [ ] Full `npx playwright test` green when secrets + flag are set
6. [ ] `env -u DATABASE_URL npm test` and `AUTH_SECRET=ci-build-placeholder npm run build` pass
7. [ ] Phase 6 marked complete in INDEX + CURRENT_FEATURE log after this feature (not before)
