# Feature 6.1: Member role and signUp helper

**Phase:** 6 — Accounts
**Status:** specced
**Estimated effort:** 3–5 hours
**Depends on:** 0.3, 0.5
**Blocks:** 6.2, 6.3, 6.4

## Goal

A third role `member` exists in the schema, and a tested `signUp` helper can create an empty personal tenant when the env flag is on. No UI.

## Scope

Include:

- `userRoles` becomes `["owner", "demo", "member"]` (Postgres enum + TS type)
- Generated Drizzle migration that **adds** the enum value (do not drop/recreate `user_role` — existing owner/demo rows must survive)
- `isSignupEnabled(env)` — only the string `true` is on; missing / anything else is closed
- Password helper: at least 12 characters (shared with 6.3)
- `signUp({ email, password }, deps)` — flag check, trim email, validate, hash, insert tenant + user in one transaction, return `{ id, email, tenantId, role: "member" }`
- Memory repository so tests pass with `env -u DATABASE_URL npm test`
- `requireTenant` accepts `member` (it follows `userRoles`; update tests)
- `.env.example` lists `AUTH_SIGNUP_ENABLED` (name only, commented off)

Exclude (for now):

- `/signup` page, login link, auto sign-in (6.2)
- `changePassword` / `/settings` (6.3)
- Playwright (6.4)
- OAuth, mailer, forgot-password, delete account
- Seeding members; Reset demo for members

## Spec

1. Tenant name for a member is the trimmed email. Unique, like `users.email`. Seed names `"Owner"` and `"Demo"` stay reserved by not being valid emails.
2. Callers never pass `tenantId`. Duplicate email (unique constraint or pre-check) throws a generic unavailable error, not “email taken”.
3. Empty email or email without `@` throws invalid-email. Password shorter than 12 throws weak-password. Flag off throws closed. Closed must not insert a tenant or a user.
4. If the user insert fails, the tenant insert rolls back (transaction on the real repo; memory repo simulates the same).
5. `npm run db:seed` still upserts only owner/demo and does not delete other tenants or users.
6. Do not log the password. Do not write `accounts` / `sessions` rows (JWT stays as today).

Typed errors (names can match the module, codes must be these):

- `closed`
- `invalid_email`
- `weak_password`
- `unavailable` (duplicate or conflict)
