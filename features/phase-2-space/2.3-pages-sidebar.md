# Feature 2.3: Pages tree in the sidebar

**Phase:** 2 — Space
**Status:** completed
**Estimated effort:** 4–5 hours
**Depends on:** 2.1, 2.2
**Blocks:** 2.4, 2.5, 2.8

## Goal

The sidebar is an expandable tree of this tenant’s pages. Users can create, rename, and delete pages (cascade nested pages after confirm).

## Scope

Include:
- Session-scoped tree: `listPagesForSession` / `getPageForSession` / create / rename / delete
- Nested pages to any depth; sibling `position`; emoji `icon`
- Create, rename, delete from the sidebar; delete confirms then removes the page and nested pages
- Clicking a page navigates to `/space/[id]`; missing/other-tenant → `notFound()`
- Creating a page **navigates first**, then refreshes the tree (reference: do not type into the old title)
- Demo seed titles appear for demo; owner tree empty
- Unit tests for create/rename/delete cascade and tenant isolation

Exclude (for now):
- Block editor (2.4)
- Database-as-page UI (2.5) — type `database`/`row` may exist in schema but sidebar can treat them as pages or hide rows
- Search (2.7)

## Spec

```ts
// createPage: parentId null | session-tenant page; position = max sibling + 1
// deletePage: other-tenant → null; cascade children (DB ON DELETE CASCADE + memory repo)
// Client never sends tenantId; requireTenant from session
```

Accessible names: `New page`, `Rename ${title}`, `Delete ${title}`.

## Implementation notes

- Do not take `tenantId` from the client.
- Rows (`type=row`) belong under a database; 2.3 may omit them from the sidebar (reference hides row pages from the tree).
