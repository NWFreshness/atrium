# Feature 7.3: tenantId indexes

**Phase:** 7 — Architecture
**Status:** specced
**Estimated effort:** 2–3 hours
**Depends on:** 7.2
**Blocks:** none

## Goal

Every tenant-scoped table has a B-tree index on `tenantId`, proven by a schema test and a generated migration. Queries do not change.

## Scope

Include:

- Drizzle `index` on `tenantId` for: `users`, `organizations`, `contacts`, `deals`, `activities`, `pages`, `blocks`, `properties`, `propertyOptions`, `rowValues`, `views`, `people`, `interactions`, `importantDates`, `facts`, `news`, `reminders`, `gifts`, `connections`
- Generated migration (`CREATE INDEX`); do not hand-write unless drizzle-kit emits something destructive
- Schema tests that each of those tables declares a `tenantId` column and an index whose columns include `tenantId`

Exclude (for now):

- Postgres RLS, policies, `FORCE ROW LEVEL SECURITY`, `SET LOCAL`
- Composite `(tenantId, id)` unless drizzle-kit’s default single-column index is what it emits — single-column `tenantId` is enough
- Changing unique indexes (`users.email`, `tenants.name`)
- Case-insensitive `lower(email)` unique index (6.1 follow-up, not this feature)
- Query helper changes, new list filters

## Files to create

- None required beyond `drizzle/` migration files drizzle-kit generates

## Files to modify

- `lib/db/schema.ts` — `users.tenantId` index
- `lib/crm/schema.ts`, `lib/space/schema.ts`, `lib/rolodex/schema.ts`
- `lib/crm/queries.test.ts` / `lib/space/queries.test.ts` / `lib/rolodex/queries.test.ts` and/or `lib/db/schema.test.ts` — index assertions (use `getTableConfig` the way existing FK tests do; assert column names, not `foreignTableName`)
- `drizzle/` — generated SQL + meta

## Spec

1. `pgTable` third argument (or equivalent in this Drizzle version) adds `index("…_tenantId_idx").on(table.tenantId)` — name stably, one per table, no two tables sharing an index name.
2. `npm run db:generate` is the source of the SQL. Read the generated file before committing: it must be `CREATE INDEX` (or `CREATE INDEX IF NOT EXISTS`), never `DROP TABLE`.
3. Existing unit tests that read table columns still pass. Do not change query signatures.
4. Groove still has no tables.

## Acceptance criteria

1. [ ] Every table listed in Scope has a `tenantId` index in the Drizzle schema
2. [ ] A test fails if one of those tables loses that index
3. [ ] Generated migration only creates indexes (no drop/recreate of enums or tables)
4. [ ] Groove schema/tests still forbid drizzle tables
5. [ ] `env -u DATABASE_URL npm test` and `AUTH_SECRET=ci-build-placeholder npm run build` pass
6. [ ] No RLS objects in the migration

## Implementation notes

- After merge, `npm run db:migrate` on the Neon **dev** URL before relying on the indexes in explain plans. Do not paste the connection string.
- `getTableConfig` FK `foreignTableName` is undefined in this Drizzle version — do not assert it. Index columns are the thing to assert.
- Do not add Tailwind, new deps, or a query planner test against live Neon.
