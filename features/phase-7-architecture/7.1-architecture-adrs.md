## Spec

Each ADR uses this shape (headings exact):

```
# ADR-NNNN: <title>
## Status: Accepted
## Context
## Options considered (benefits / costs)
## Decision
## Consequences (+ / −)
## Reversal trigger
```

Content that must be true (paraphrase, do not invent a different decision):

1. **0001 Modular monolith on Next + Neon.** Reject Express/SQLite (no durable disk on Vercel). Reject per-app services (no independent deploy, scale, or team; would still share auth + one Postgres). Quantum is the whole app + the shared database.
2. **0002 neon-http, not interactive transactions.** `db.transaction()` throws. Multi-statement writes use `db.batch`; ids are generated in application code. Reversal: leave Vercel, or Neon offers a pooled driver we adopt in a spec.
3. **0003 JWT session, no revocation on password change.** `tenantId` and `role` live on the token. A changed password leaves other 30-day cookies valid. Reversal: a stolen-cookie incident or a “sign out everywhere” product request.
4. **0004 Groove has no tables.** Web Audio only; no seed, no resetter, no `tenantId` on Groove state. Reversal: we need saved patches per tenant (that is a new phase, not a silent table).
5. **0005 Signup fail-closed + force-dynamic pages.** Only the string `true` opens signup. `/login` and `/signup` export `dynamic = "force-dynamic"`. Reversal: a mailer or always-on public signup phase.
6. **0006 Application tenancy; RLS deferred.** Queries take `tenantId` from the session. RLS is not installed because neon-http cannot persist `SET LOCAL`. Reversal: a driver that holds GUC per request, or a missed-predicate incident we choose to backstop in Postgres.

C4 rules: title names the view; every box has a responsibility; every arrow has protocol (cookie, HTTPS, Neon HTTP, Web Audio); people are on the context view. Text, not AWS icon soup.
