## Spec

Each ADR uses this shape (headings exact):

```
# ADR-NNNN: <title>
## Status: Accepted
## Context
## Options considered (benefits / costs)
## Decision
## Consequences (+ / −)
## Reversal trigger
```

Content that must be true (paraphrase, do not invent a different decision):

1. **0001 Modular monolith on Next + Neon.** Reject Express/SQLite (no durable disk on Vercel). Reject per-app services (no independent deploy, scale, or team; would still share auth + one Postgres). Quantum is the whole app + the shared database.
2. **0002 neon-http, not interactive transactions.** `db.transaction()` throws. Multi-statement writes use `db.batch`; ids are generated in application code. Reversal: leave Vercel, or Neon offers a pooled driver we adopt in a spec.
3. **0003 JWT session, no revocation on password change.** `tenantId` and `role` live on the token. A changed password leaves other 30-day cookies valid. Reversal: a stolen-cookie incident or a “sign out everywhere” product request.
4. **0004 Groove has no tables.** Web Audio only; no seed, no resetter, no `tenantId` on Groove state. Reversal: we need saved patches per tenant (that is a new phase, not a silent table).
5. **0005 Signup fail-closed + force-dynamic pages.** Only the string `true` opens signup. `/login` and `/signup` export `dynamic = "force-dynamic"`. Reversal: a mailer or always-on public signup phase.
6. **0006 Application tenancy; RLS deferred.** Queries take `tenantId` from the session. RLS is not installed because neon-http cannot persist `SET LOCAL`. Reversal: a driver that holds GUC per request, or a missed-predicate incident we choose to backstop in Postgres.

C4 rules: title names the view; every box has a responsibility; every arrow has protocol (cookie, HTTPS, Neon HTTP, Web Audio); people are on the context view. Text, not AWS icon soup.

Two independent subagent reviews ran before the commit — spec compliance, then
quality. Spec compliance passed criteria 1–5 and could not verify 6 (controller-owned).
The quality review found no blocking issue; its three should-fix items were fixed:

- **The README's precedence rule argued against its own authority line** ("the design
  is the authority … if an ADR and the design disagree, fix the design first"). Now:
  the design outranks the ADRs — fix the ADR, or amend the design first if the
  decision genuinely moved, which is the rule the design itself applies to specs.
- **The container view asserted a boundary that does not hold yet** — "No database
  client, no tenantId, no Drizzle" for Browser JavaScript, while the design records
  the live leak (`/rolodex/circles` → `move-person.ts` → `queries.ts`). The box now
  says the client chunk *must not* carry Drizzle, names 7.5, and admits the leak it
  has today.
- **ADR-0003 misattributed the `sessions` table.** It was kept so OAuth can be added
  later (parent design, §Auth and data), not "for exactly this kind of change".

Nine further review nitpicks were fixed rather than recorded: the level-2 arrowheads
pointed opposite their labels; ADR-0005 called the flag check the action's "first
statement" when it is the first *guard* (`app/signup/actions.ts` trims three fields
first); ADR-0006 said the query modules are 900–1200 lines when `lib/space/queries.ts`
is 1217; ADR-0004 called Groove "the first app added after that pattern was
established" (Space and Rolodex were too — Groove is the first that did not adopt it);
ADR-0004's claim that the reference implementation keeps no saved patches was
unverifiable from this workspace, so it was re-checked against that repository's tree
(client-only Groove, no server module) and rewritten; ADR-0001's trigger was
unmeasurable ("measurably punishes") and now names a signal; Web Audio is annotated as
in-process instead of being silently absent from the C4.

### The one finding this feature does not accept

Spec compliance flagged `HANDOFF.md` as a scope violation, reading the spec's Exclude
line ("Changing HANDOFF beyond the usual feature-close later; this feature only adds
`docs/adr/`") as "do not touch HANDOFF at all". Not accepted, deliberately: the three
most recent feature PRs each updated HANDOFF's stop-line, "Where we are", read-order
item and closing line in the same PR (6.2 `956f0c2`, 6.3 `5dd1541`, 6.4 `e317ed8` —
`git show --stat` on each), and a HANDOFF left saying "Nothing is in progress … do not
implement 7.1 until this docs PR is merged" would send the next session to a feature
that is already done. What the Exclude line does forbid is untouched: the parent design
is not rewritten, 7.2–7.5 stay `specced`, and the phase is **not** marked complete in
`INDEX.md`.

### Deliberate limits

- **Nothing automated guards these records.** `npm test` cannot see `docs/adr/`, so
  every check above was run by hand for this PR: no test asserts that the six files
  exist, that their headings match the shape, or that a later change has not silently
  contradicted the design. A `tests/adr.test.ts` in the shape of
  `tests/workroom-namespace.test.ts` would lock all three, but this spec's "Files to
  create" is an explicit docs-only list and its Goal says "no application code", so it
  was left out rather than added unasked. Worth a follow-up if the records start
  drifting — this is the same class of gap the repo closed for phase 5 with a
  source-grep test.
- **The C4 is prose and ASCII.** No Structurizr, PlantUML, HTML or mermaid (the spec
  excludes them), so box responsibilities and arrow protocols live in the table under
  each diagram, and the arrowheads have to be read with it.
- **`docs/adr/README.md` is 162 lines**, above the ~80 the spec asks of each record;
  the guideline is per ADR, and the README carries the index plus both C4 views.
- **ADR-0001's threshold is a chosen number, not a measurement.** "More than ~50 kB
  gzip" is a trigger someone has to measure when the question comes up; the ADRs claim
  nothing about today's bundle sizes.
