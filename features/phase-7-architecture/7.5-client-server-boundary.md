## Goal

Nothing under `components/` value-imports Drizzle, `getDb`, schema tables, query CRUD, seed, or reset. `/rolodex/circles` no longer ships `drizzle-orm` in its client chunk. A source-grep test locks the rule.

## Scope

Include:

- A Vitest source-grep (same style as Groove’s “no drizzle” test and the Accounts messages-module type-only import test) over `components/**/*.{ts,tsx}`
- Forbidden *value* imports: `lib/db`, `lib/*/queries`, `lib/*/schema`, `lib/*/seed`, `lib/*/reset`, `drizzle-orm`, `@neondatabase/serverless`
- `import type { … }` from those modules is allowed
- `"use server"` modules are not under `components/` today; keep it that way
- Fix the known leak: `components/rolodex/circles-board.tsx` imports `circleColumnStats` from `lib/rolodex/move-person.ts`, which value-imports `getPerson` / `updatePerson` from `queries.ts`. Move the pure stats helper (and any other pure function the board needs) to a module that does not import `queries.ts`
- Optional: `lib/{crm,space,rolodex}/types.ts` for row types if that keeps client `import type` off `queries.ts`. Not required if `import type` from the barrel stays type-only after 7.4

Exclude (for now):

- eslint-plugin-boundaries, dependency-cruiser, or a new lint stack
- Rewriting server actions
- Forbidding `import type` from `queries.ts`
- Bundle-size budgets in CI
- Groove audio rules beyond what 4.x already tests

## Shipped notes

The rule is enforced by `lib/client-boundary.test.ts`, and the leak it was written
for is gone.

**The gate.** It is a scanner, not a set of regexes over raw text. Comments are
removed by a small state machine that understands string literals and regex
literals (so `const OPEN = "/*"` cannot delete the import between it and
`const CLOSE = "*/"`, and a `/["']/` cannot desynchronise the walk); string
interiors are remembered as spans. Then every module reference is read — static
`import` / `export … from`, side-effect `import "x"`, and `import("x")` /
`require("x")` — with **no semicolon required** anywhere, because a file without
punctuation is still valid TypeScript. A reference survives into the bundle unless
the whole clause is type-only: `import type { A }` **and** `import { type A }` are
both erased, while a mixed `import { type A, B }` counts as a value import, because
it is one. Text that only *looks* like an import — the same statement quoted inside
a template literal — is rejected by span position. A dynamic import whose target is
not a plain literal is reported as unreadable and fails the gate rather than being
assumed harmless.

It then walks the value-import graph rather than checking one file: from all 81
files under `components/`, following relative and `@/` specifiers into `lib/`
(139 files visited) and stopping at `"use server"` modules, which Next replaces
with an RPC stub. `lib/db`, `lib/{crm,space,rolodex}/{queries,schema,seed,reset}`,
`drizzle-orm` and `@neondatabase/serverless` are rejected by specifier **and** by
resolved path, so `../../lib/db` and `@/lib/crm/queries-drizzle` are caught too.

**It was red before the fix.** Against `main`, the gate reported exactly:

```
[ "lib/rolodex/move-person.ts → ./queries (query CRUD / schema / seed / reset)" ]
```

**Thirteen probes, applied and then reversed byte-identically** (`diff -q` after
each restore), because "the test passes" says nothing about whether it bites:

| Probe — the board made to… | Result |
| --- | --- |
| value-import `move-person.ts` again (the transitive chain) | **FAIL** — names `lib/rolodex/move-person.ts → ./queries` |
| value-import `@/lib/rolodex/queries` directly | **FAIL** |
| side-effect `import "@/lib/rolodex/queries"` | **FAIL** |
| `import { type PersonComputed } from "@/lib/rolodex/queries"` | **PASS** — type-only is erased |
| value-import `@/lib/db` | **FAIL** |
| `import("@/lib/rolodex/queries")` (dynamic) | **FAIL** |
| `export * from "@/lib/rolodex/queries"` | **FAIL** |
| a whole file written without semicolons | **FAIL** |
| a second statement after a `;` on the same line | **FAIL** |
| the import between two strings that spell comment markers | **FAIL** |
| the same import quoted *inside* a template literal | **PASS** — no false positive |
| `import(name)` — a target that cannot be read | **FAIL** |
| a regex literal containing quotes, then a value import | **FAIL** |

The dynamic-import and re-export probes were added after the first pass: the parser
originally read only static statements, and `await import(…)` walked straight past
it. Probes H–M came from the adversarial review and two of them broke that first
implementation: it required a terminating `;`, so semicolon-free files and
same-line statements were invisible, and it stripped comments with three
position-blind regexes. Both are fixed; the last probe then caught a bug introduced
*by* the fix — a regex detector that tested the last character instead of the last
non-space character, which silenced the walk again. Only a probe finds that.

**The fix.** `circleColumnStats` moved to `lib/rolodex/circle-stats.ts`.
`move-person.ts` keeps only `movePersonCircle` — it may import `queries.ts`,
because it is not a client module — the board imports the stats from the new file,
and the `circleColumnStats` describe block moved to
`lib/rolodex/circle-stats.test.ts` beside it. The spec's optional `lib/*/types.ts`
was not needed: 7.4 left `import type` from the barrel genuinely type-only, and the
gate now enforces the *kind* rather than the spelling, so `circle-stats.ts` takes
`PersonComputed` from the barrel like the other 18 consumers — drop the `type` and
the gate fails, naming the file.

**Gates.** `env -u DATABASE_URL npm test` → **639 passed (101 files)**, up from 633
(99) — six tests, five of them the gate's and one for the unreadable-dynamic case,
and the moved test case keeps its own count. `npm run build` exit 0,
`git diff -- package.json package-lock.json` empty, prettier run on each touched
path individually (never a directory).

### Review round

Two subagents ran against the finished gate: spec compliance, and an adversarial
pass that tried to smuggle a value import past it. Compliance reported all five
acceptance criteria PASS with file:line evidence, all four Spec items satisfied
(including that `app/` is never seeded, so Server Components there may still import
queries), and one process note: at review time the work was uncommitted in the
working tree, which is this session's habit — the commit follows.

The adversarial pass **did break it three ways**. All three are fixed and each has
a probe above: a semicolon-free file produced *zero* imports (the parser demanded a
terminating `;`); a statement after a `;` on the same line was invisible; and the
comment stripper was string-blind, so `const OPEN = "/*"; … const CLOSE = "*/";`
deleted the import between them. It also showed that `import(name)` and
`import(\`…\`)` slipped through, which the unreadable-dynamic rule now fails on.
Two of its findings are **deliberate, not fixed**:

- **`queries-shared.ts` is forbidden to components**, though it has no runtime
  Drizzle import today. The spec's own regex is that broad, and the strictness
  pushes a client that needs a pure helper toward the pattern this feature
  established — lift the helper into its own module, as `circleColumnStats` was.
  If `queries-shared` ever gains a runtime import of Drizzle, the walk catches it
  transitively anyway.
- **An unresolvable relative or `@/` specifier fails the gate** (`@/lib/db.js`,
  `?url` imports) rather than being skipped, and **bare specifiers are trusted**:
  `#db` (a package.json `imports` entry) and any future tsconfig alias resolve to
  nothing and are treated as packages. That direction is chosen — an import the
  gate cannot resolve is one it cannot vouch for, so it fails loudly — and the
  blind spot is recorded because today the repo has exactly one alias (`@/*`) and
  no `imports` field; closing it means teaching the gate to read `tsconfig.json`.

Its last finding was a real inaccuracy, and is fixed: the first version of
`circle-stats.ts` took `PersonComputed` from `queries-shared` and its comment
claimed the module had no edge to the database layer "at all, not even a type
edge" — misleading, since type edges are erased by definition and `queries-shared`
itself has `import type` edges to `drizzle-orm`. It now follows the repo's
convention.

**One negative result, recorded rather than dressed up.** A bundle-level probe
(grepping `.next/static` for `tenantId is required`, which lives only in the three
`queries-shared` modules) found the marker in **no** client chunk — in the fixed
build *and* in the pre-fix build. So it does not demonstrate the fix; it is
inconclusive. The likely reason is that the production bundler tree-shakes
`move-person.ts`'s unused sibling export, since `circleColumnStats` never touches
`queries`; route client chunks are also hash-named, so "the `/rolodex/circles`
chunk" is not addressable by path. This is exactly why the spec chose a source-grep
as the fitness function and said not to build CI on chunk inspection. What is
claimed here is what was measured: the *edge* is gone and the gate keeps it gone —
not a measured bundle-size change, and not a claim about what dev-mode chunks
carried.
