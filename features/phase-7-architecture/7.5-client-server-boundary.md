# Feature 7.5: Client/server import boundary

**Phase:** 7 — Architecture
**Status:** specced
**Estimated effort:** 3–4 hours
**Depends on:** 7.4
**Blocks:** nothing

## Goal

Nothing under `components/` value-imports Drizzle, `getDb`, schema tables, query CRUD, seed, or reset. `/rolodex/circles` no longer ships `drizzle-orm` in its client chunk. A source-grep test locks the rule.

## Scope

Include:

- A Vitest source-grep (same style as Groove’s “no drizzle” test and the Accounts messages-module type-only import test) over `components/**/*.{ts,tsx}`
- Forbidden *value* imports: `lib/db`, `lib/*/queries`, `lib/*/schema`, `lib/*/seed`, `lib/*/reset`, `drizzle-orm`, `@neondatabase/serverless`
- `import type { … }` from those modules is allowed
- `"use server"` modules are not under `components/` today; keep it that way
- Fix the known leak: `components/rolodex/circles-board.tsx` imports `circleColumnStats` from `lib/rolodex/move-person.ts`, which value-imports `getPerson` / `updatePerson` from `queries.ts`. Move the pure stats helper (and any other pure function the board needs) to a module that does not import `queries.ts`
- Optional: `lib/{crm,space,rolodex}/types.ts` for row types if that keeps client `import type` off `queries.ts`. Not required if `import type` from the barrel stays type-only after 7.4

Exclude (for now):

- eslint-plugin-boundaries, dependency-cruiser, or a new lint stack
- Rewriting server actions
- Forbidding `import type` from `queries.ts`
- Bundle-size budgets in CI
- Groove audio rules beyond what 4.x already tests

## Files to create

- `lib/rolodex/circle-stats.ts` (or similar) — `circleColumnStats` only
- `components/client-imports.test.ts` (or `lib/client-boundary.test.ts`) — the grep

## Files to modify

- `components/rolodex/circles-board.tsx` — import stats from the pure module
- `lib/rolodex/move-person.ts` — stop exporting the pure helper, or re-export from the new file without pulling it the other way into the client
- Any other `components/` file the grep fails on

## Spec

1. Walk `components/` `.ts`/`.tsx` files. Strip `import type { … }` and `import { type X }` type-only specifiers. Remaining import sources must not match `/lib\/db\b/`, `/lib\/(crm|space|rolodex)\/(queries|schema|seed|reset)\b/`, `drizzle-orm`, `@neondatabase/serverless`.
2. `circleColumnStats` has no `getDb` / `queries` import. `movePersonCircle` may keep using queries; the board must not import `move-person.ts` if that file still value-imports queries.
3. The test would have failed on current `main` (prove it once in the PR: red on the leak, then green after the split). Reverse the probe before committing.
4. Server Components under `app/` may import queries; this feature does not grep `app/`. Client components live in `components/`.
