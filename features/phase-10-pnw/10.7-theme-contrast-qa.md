# Feature 10.7: Contrast gate, theme QA, and smoke

**Phase:** 10 — PNW (redesign)
**Status:** specced
**Estimated effort:** 4–6 hours
**Depends on:** 10.2, 10.3, 10.4, 10.5, 10.6
**Blocks:** nothing

## Goal

Close the phase with gates that can actually bite: a unit test that computes WCAG contrast from the real token values, the espresso-era assertions retired across every existing gate, and a browser walk that proves both themes, the type stack, and the no-console rule hold on all thirteen screens.

## Scope

Include:

- **New computed-contrast gate** `tests/theme-contrast.test.ts`:
  - parse the token blocks out of `app/globals.css` (`:root` and `[data-theme="light"]`) and the instrument block out of `components/groove/groove-shell.module.css`
  - compute WCAG 2.1 relative-luminance contrast for a declared list of role pairs: `--ink`, `--ink-dim`, `--ink-faint`, `--brass`, `--clay-ink`, `--slate`, `--timber` against `--bg-0`, `--bg-1`, `--bg-2`, `--bg-3` in both themes, and `--inst-ink` / `--inst-dim` / `--inst-faint` / `--inst-brass` against `--inst-panel`
  - thresholds: **4.5:1** for text roles, **3.0:1** for declared UI/fill roles — with the fill-only exceptions written into the test as named pairs (`--brass-deep` on dark `--bg-0`, `--clay` on dark `--bg-0`) so relaxing one requires editing the exception list, not the threshold
  - failure messages carry the measured ratio and the pair, e.g. `--ink-faint on --bg-2 = 3.94:1 (need 4.5)`
- **Retire the espresso assertions** in every gate that hardcodes them: `app/globals.test.ts` (token values + type-stack variables), `tests/workroom-namespace.test.ts` (full colour-token set per theme, the retired-hex list gains `#13100c`, `#1b1712`, `#231e16`, `#2b251b`, `#f0e9da`, `#ece5d6`, `#262015`, `#a86f14`; the chart-palette assertion moves to the PNW values), `components/{crm,space,rolodex,groove}/*-pass.test.ts` if 10.3–10.6 did not already update them, and `e2e/workroom.spec.ts`'s ground constants
- **New type assertions**: `app/globals.test.ts` (or `app/pnw-tokens.test.ts`) asserts the stack mapping (`--font-display: var(--font-outfit)`, `--font-sans: var(--font-archivo)`, `--font-mono: var(--font-geist-mono)`) and that the type-scale tokens exist with their sizes/tracking; `e2e/workroom.spec.ts` asserts the **computed** `fontFamily` of an `h1` (Outfit), a body paragraph (Archivo), and a mono label (Geist Mono) — the gate that catches a silently failed font load, which no source-grep can see
- **Browser QA** in `e2e/workroom.spec.ts`: dark = basalt `rgb(37, 40, 42)`, light = mist `rgb(238, 241, 242)` (both replacing the espresso/paper constants), theme survives reload, Groove stays dark in light with the PNW instrument values, the existing link-walk, the existing thirteen-screen no-console walk, plus a `prefers-reduced-motion: reduce` pass asserting the card stagger and the sky drift are inert
- **Contrast gate proven by injection**, not by reading it twice: flip `--ink-faint` dark to `rgba(163,177,155,.62)`, copy a dark accent into the light block, drop `--clay-ink`, and raise a declared fill exception to a text role — each must fail, and each probe must be reversed byte-identically

Exclude (for now):

- Screenshot goldens / visual-diff baselining (deferred since 5.7, still not a blocker)
- Re-litigating the palette or the type pairing in this feature — the design doc is the authority; this is the gate
- New product features or copy beyond what 10.1–10.6 defined
- Automated checks for claims that cannot be honestly automated: the "one golden element per screen" rule stays a review/read criterion, and this feature says so rather than asserting something weak

## Spec

1. The contrast gate reads the **shipped CSS**, not a copy of the values. If a token is renamed, the gate fails with "token missing" rather than silently skipping the pair.
2. Thresholds are per role, and the exceptions are explicit: text roles 4.5, UI/fill roles 3.0, and every downgrade names the token and the theme it applies to. There is no global "ignore" switch.
3. A gate that cannot be broken by injection is not a gate. Each probe listed above is applied, observed failing with the expected message, and reversed; the result is recorded in the feature's shipped notes.
4. The type assertion runs in the browser because font loading is a runtime event: a source-grep cannot tell a loaded Outfit from a fallback `Helvetica Neue`.
5. The reduced-motion pass uses Playwright's `emulateMedia({ reducedMotion: "reduce" })` and asserts the computed `animation-name` is `none` on a `.reveal` element and that no transform animation runs on the sky layer.
6. The no-console walk gains nothing new to visit — it must stay green with the new sky layer, which is the likeliest source of a stray console error or a hydration mismatch (SSR/CSR drift on a random-free deterministic layer only; no `Math.random`, no `Date.now` in render).
7. This feature closes Phase 10: its acceptance criteria must hold with `.env` secrets locally, and the controller re-runs the suite rather than trusting the implementer's report.

## Implementation notes

- `tests/workroom-namespace.test.ts` is the 5.7 gate; keep its 13 assertions intact and extend the hex list rather than rewriting it. Its per-theme "full colour-token set" check is exactly what makes a half-finished theme fail here.
- The instrument scope needs its own pair list: the gate reads `groove-shell.module.css` separately because those tokens never appear in `globals.css`.
- Where the QA finds a real contrast failure, fix the token in the owning feature and re-run — the precedent is 5.7, which fixed palette drift in the feature that owned it and re-verified by injection.
- Timeouts: `/rolodex` renders slowly against the loaded dev DB, and the walks touch thirteen screens. Use the existing 20 s nav timeout and the 180 s walk cap; do not raise them to hide a regression.
