# Feature 10.2: Shared chrome, launcher, and login

**Phase:** 10 — PNW (redesign)
**Status:** completed
**Estimated effort:** 3–5 hours
**Depends on:** 10.1
**Blocks:** 10.3, 10.4, 10.5, 10.6, 10.7

## Goal

The product's frame reads as PNW before any app is touched: a top nav with a carved wordmark, four launcher cards that describe the apps, and a login screen with the golden hour on it. This is also the pass that proves the type pairing in place — if Outfit/Archivo reads generic here, the phase's documented alternative (see the design doc's Decisions table) is a two-line flip in 10.1.

## Scope

Include:

- `components/atrium-nav.tsx` + `atrium-nav.module.css`: sticky translucent strip over basalt/mist, brass diamond brand, Outfit wordmark, five nav links in Archivo with a **golden** active underline (the one highlight on the screen), identity chip → `/settings`, Theme / Reset demo / Logout as `atrium-btn` controls
- `app/workroom.css` → the shared presentational layer keeps its `atrium-` class names, restyled onto the PNW tokens: `atrium-btn` / `atrium-btn-primary` / `atrium-field` / `atrium-panel` / `atrium-label` / `atrium-chip` / `atrium-avatar` / `atrium-kpi` / `atrium-subnav` / `atrium-subtab` / `atrium-pagetitle` / `atrium-appcard`. Rename the file's header comment only; **do not rename the file** (5.7's namespace gate resolves imports by path)
- `app/(authenticated)/page.tsx` launcher: four cards with inline SVG glyphs, per-card accent (`--clay`, `--moss`, `--slate`, `--brass`), a one-line description each, hover edge in `--brass`, staggered `reveal`
- Login: the oversized brand mark, the clearing-sky layer behind it, `atrium-field` inputs with visible focus rings (golden), `atrium-btn-primary` = golden fill with charcoal text, error alert in `--clay-ink`
- Type application: display scale on the launcher/login hero, `--text-h2` on section headings, mono labels on every data line, tabular numerals on KPI figures

Exclude (for now):

- All per-app surfaces (10.3–10.6)
- Groove's instrument tokens (10.6) — the desk stays espresso-dark in this pass
- Any auth, session, tenancy, or route change; the login server action and the field names are untouched
- New marketing copy beyond the four one-line app descriptions

## Spec

1. The nav keeps its accessible structure: `role="navigation"` with `aria-label="Atrium"`, five links with the exact labels `Home`, `CRM`, `Space`, `Rolodex`, `Groove` (Playwright matches them with `{ exact: true }`), and the Theme button keeps `aria-label="Toggle theme"`. 5.7's link-walk must pass untouched.
2. Exactly one golden element per screen: the active nav underline. Links, cards, and controls hover into `--ink` / `--line-strong`, not into golden; the primary button is the exception only on the login/signup stage, where it is the only action.
3. The wordmark is Outfit 700 at `--text-h3` scale with `-0.02em` tracking; the brand diamond stays a 7px golden square rotated 45°, `aria-hidden`.
4. The launcher cards use `--clay-ink` / `--moss` / `--slate` / `--brass` as their top rule and glyph stroke; the card body stays on `--bg-1`, hover lifts the border to `--brass` and the shadow to the new cool panel shadow.
5. Login/signup: fields are `atrium-field` with a visible `:focus-visible` ring in `--brass` at 2px (WCAG 2.4.11 — the current module has no focus-visible style worth keeping); the alert text is `--clay-ink`; the page keeps `export const dynamic = "force-dynamic"` on both auth pages.
6. `prefers-reduced-motion: reduce` disables the card stagger and the sky drift, as in 10.1.
7. No behaviour changes: same server actions, same field `name`s, same error copy, same redirects. This pass is presentation only.
