## Spec

1. Every surface resolves a PNW token; no bare hex in the CRM modules except the four chart literals in the two chart components (10.1 lists them, 10.7 greps for strays).
2. Status tones are semantic, not decorative: overdue/late = `--clay-ink`, won = `--brass`, open/in-pipeline = `--moss`, neutral = `--slate`. The pipeline board's six stages step through the same family rather than six unrelated hues.
3. One golden element per screen: the active subnav underline; the KPI tile whose value matters most may take a golden top rule instead of a chart series colour, never in addition.
4. Tables keep their density: 44px rows, mono numerals right-aligned with `tabular-nums`, headers at `--text-label` in `--ink-faint`. Archivo's narrower advance (497/1000em) buys ~7 % more characters per column than Inter — do not spend it on larger type.
5. Charts label each series directly (legend row with name + value) because PNW series differ by hue, not luminance (measured 1.0–1.29 apart).
6. Hover states use `--line-strong` / `--bg-2`; focus-visible uses a 2px `--brass` ring everywhere an element is interactive.
7. Behaviour is frozen: same queries, same tenant scoping, same dialogs, same labels that Playwright matches (`Edit {name}`, `Delete {name}`).

- Charts are the only place colour is load-bearing for meaning. Everywhere else it is hierarchy.
- If a KPI figure in the display face wraps at 375px, drop it to `--text-h2` rather than shrinking the label.
