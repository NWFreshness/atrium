# Feature 10.1: PNW tokens, type stack, and theme scaffold

**Phase:** 10 — PNW (redesign)
**Status:** completed
**Estimated effort:** 4–6 hours
**Depends on:** nothing
**Blocks:** 10.2, 10.3, 10.4, 10.5, 10.6, 10.7

## Goal

The foundation of the PNW theme: the basalt/mist palette, the Outfit + Archivo + Geist Mono type stack, a documented type scale, and the measured usage rules that say which token may be used as text — all in the app's global token block, with no screen restyled yet. Every later pass consumes these tokens.

## Scope

Include:

- The palette, defined once at the document root, in **two directions**:
  - **dark = basalt** (`--bg-0 #25282a`), surfaces moss-cast upward (`--bg-1 #2b3330`, `--bg-2 #313b37`, `--bg-3 #39443f`), lines `rgba(163,177,155,.16)` / `.30`
  - **light = mist** (`--bg-0 #eef1f2`), surfaces up to white (`--bg-1 #f5f7f8`, `--bg-2 #fbfcfc`, `--bg-3 #ffffff`), lines `#c9d2d0` / `#a9b6b3`

- Geometry sharpened for the architectural read: `--r-sm 4px`, `--r-md 6px`, `--r-lg 10px` (was 8/12/16), `--shadow-panel` re-cast from a warm shadow to a cool one
- Atmosphere: keep the grain overlay at lower opacity (`0.05` dark / `0.035` light); replace the top brass glow with a **clearing-sky** layer (moss → cedar → golden radial wash) that drifts on a 46 s alternate loop, disabled entirely under `prefers-reduced-motion: reduce`
- The two usage rules the studies produced, written into the token block as comments so a later pass cannot "helpfully" break them:
  1. **One highlight per screen.** `--brass` (golden) marks the single most important thing on a view — active nav item, a win, the primary button. Nothing else uses it.
  2. **Dark moss is a surface; light moss is ink.** `#2d4a3e` is 1.53:1 on basalt and 8.56:1 on mist. Any rule that flips it must fail 10.7's contrast gate.

- Restyling any screen (10.2–10.6)

- Removing the Workroom espresso values from git history, or renaming the `atrium.theme` storage key
- Any database, domain, route, or behaviour change
- Screenshot goldens / visual-diff baselining (still deferred, per 5.7)
- Adding any font-weight or family beyond the three named stacks; no second sans, no serif fallback stack for headings beyond a system-serif guard

## Spec

1. Replace the `:root` token block and the `[data-theme="light"]` block with the values in the table above. Token **names stay** where the app already has them (`--bg-*`, `--ink*`, `--line*`, `--brass*`, `--moss`, `--clay`, `--slate`, `--good/--warn/--bad`, `--font-display/sans/mono`, `--r-*`, `--shadow-panel`, `--background/--foreground`); only `--violet` is retired and `--clay-ink` / `--timber` are added. Four per-app CSS modules and every screen must keep compiling against this block unchanged.
2. Every text-role token must clear 4.5:1 against the **lightest surface it is used on** in that theme, not merely against `--bg-0`. That is why the dark `--ink-faint` is a solid lichen rather than a dimmed `rgba()`: a 62 %-opacity lichen measures 2.96:1 on a `--bg-2` panel, and WCAG has no micro-label exemption.
3. The light theme derives its own cedar/golden/lichen text values (`--clay-ink #8f5138`, `--brass #8a6320`, `--ink-faint #5f6b5a`). Copying the dark accents into light mode is the failure this feature exists to prevent: `#b87355` is 3.29:1 on mist and `#dfa84a` is 1.88:1.
4. Fills and text are separate tokens. A solid button in light mode is `--brass-bright`-on-`--bg-*` with **charcoal text on the bright pigment** (charcoal on `#dfa84a` = 6.95:1), never the dimmed golden as a fill (charcoal on `#8a6320` = 2.75:1, which is what the palette study's first cut shipped and its own QA caught).
5. Data series are separated by **hue**, not luminance — measured, lichen/cedar/rain/timber sit within 1.0–1.29 of each other in luminance. So: every chart must label each series directly (value or name at the mark or in the legend row), and the two chart components' four literals move to `#a3b19b` / `#e0a488` / `#8b9fc2` / `#b9ab93` on dark and `#4f5f48` / `#8f5138` / `#46608a` / `#6a5c48` on light. Colour is never the only channel.
6. The type stack wins on the measured x-height argument: Archivo's 53 % x-height against Inter's 55 % at 16px is within a step, while Archivo's advance (497/1000em) is 7 % narrower — a four-column CRM table fits more characters before it wraps. Outfit (49 % x-height, 522/1000em) is the geometric half of the brief without Montserrat's 601/1000em width.
7. `--font-display` / `--font-sans` / `--font-mono` keep their names and point at the new families. The fallback stacks are guard rails only (`Helvetica Neue`, system serif, `ui-monospace`) — the product never renders them unless a font request fails.
8. Keep the `reveal` stagger (`--i`, 70 ms) and the `prefers-reduced-motion` guard; add the sky layer inside the same guard so the drift stops for reduced-motion users.
9. No CSS module outside the four chart literals is touched. The foundation must compile against the current per-app styles with no visual regressions beyond inherited body colors.
