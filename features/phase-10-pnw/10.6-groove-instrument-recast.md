## Goal

The groovebox is recast as a piece of dark anodised hardware that belongs to the same product as the rest of the theme — basalt chassis, lichen meters, cedar for overload, golden for the lit play LED — while keeping its own instrument token set and staying dark under `data-theme="light"`.

## Scope

Include:

- `components/groove/groove-shell.module.css`: replace the 15 espresso-era `--inst-*` values (the table below lists 14 rows plus `--inst-clay-deep`, added in review) with the PNW instrument set. The light-theme overrides **stay absent** — this desk does not re-skin for paper, and 5.6 removed those overrides deliberately
- Chassis, nameplate, corner screws, transport bar, four unit cards (`RHYTHM DR-16`, `BASS MB-1`, `PADS PX-4`, `LEAD LX-2`), master strip, scope canvas borders
- `components/groove/transport.tsx` play LED: lit = `--inst-brass` (golden), unlit = `--inst-line`; the STOP/PLAY labels and aria states unchanged
- `components/groove/master.tsx`, `scope.tsx`: knob arcs in `--inst-ink`, sweep meter in `--inst-brass` → `--inst-clay` above the overload threshold, scope trace in `--inst-moss`
- Keep every bare `groove-*` DOM class as a literal via `:global()`; keep the four units' equal heights (`align-items: stretch` + `margin-top: auto`)

## Spec

1. The instrument set is a nested scope, not a re-skin of the app: `--inst-*` live in `groove-shell.module.css` and never fall back to `--bg-*`/`--ink*`. A missing instrument token must be a visible failure in review, not a silent inheritance from the PNW app theme.
2. The desk stays dark under `data-theme="light"`: no `[data-theme="light"]` block in the instrument ruleset. 10.7's namespace gate asserts the absence explicitly (5.6 built that assertion; this feature must not weaken it).
3. Bare `groove-*` class names stay literal via `:global()`. `e2e/groove.spec.ts` selects `.groove-master-leds .groove-led` and tests `className.includes("on")`, so hashing these names silently breaks the smoke — 5.6 shipped that bug once.
4. The lit/unlit LED contrast is the one measured pair inside Groove: `--inst-brass #dfa84a` against `--inst-panel #23282a` must stay ≥3:1 (**it measures 6.99:1** — this spec's original "5.6:1" was wrong), and the unlit state must remain distinguishable by shape, not only colour (the LED keeps its inset ring).
5. Warmth moves from brass-orange to PNW golden/cedar; the chassis goes cool (basalt) rather than warm-brown. Nothing else about the desk changes: same dimensions, same unit heights, same playhead behaviour.
6. `e2e/groove.spec.ts` (8 tests) must pass unchanged except for any assertion that hardcodes an instrument value — and the only such assertions are the two in `e2e/workroom.spec.ts` named above, which this feature updates in the same commit.

## Shipped notes

The desk's `--inst-*` scope carries the PNW instrument values from the spec table; no light-theme override exists in the instrument ruleset, so the desk stays dark under `data-theme="light"` while the app around it turns to mist. Bare `groove-*` names stay literal via `:global()`, and the `.groove-led` / `on` contract `e2e/groove.spec.ts` selects is unchanged. `--groove-accent` became `var(--inst-ink)` for the knob value arc (spec line 20: "knob arcs in `--inst-ink`"). Espresso-era literals that were never `--inst-*` tokens were mapped to the instrument family (chassis gradients, play/tempo/mute faces, pad velocity steps, fader caps, and the scope canvas's cyan trace/grid/spectrum → `--inst-moss` / PNW line / rain slate).

Verified by the controller: `env -u DATABASE_URL npm test` **741 passed** (110 files), build exit 0. The lit-LED pair `#dfa84a` on `#23282a` measures 6.98:1 (≥3:1), computed in the new gate.

**Spec-compliance review found three things, all fixed in this commit:**
1. **The one surviving espresso literal was outside the gate's reach.** `components/groove/knob.tsx` still carried `var(--groove-accent, #ecad0a)` — the pre-5.6 amber — which the new gate could not see because it scanned only the stylesheet. Spec item 1 says a missing instrument token must fail visibly, not fall back to a stale colour; the fallback is now `#eef1f2` (the PNW ink) and the gate scans the desk's components, not just the CSS. Probed: restoring the amber fails the gate.
2. **A hardcoded value in the instrument file.** `--groove-accent`'s mute gradient ended on a literal `#8f5138` (the light theme's `--clay-ink`, borrowed into a scope that never re-skins). It is now a declared `--inst-clay-deep` token, so it moves with the instrument set.
3. **The app-token guard was weaker than it read.** `/var\(--(bg-[0-9]|ink|line|brass|moss|clay|slate|timber)[),]/` only matched a token followed immediately by `)` or `,`, so `var(--ink-dim)`, `var(--line-strong)` and `var(--brass-soft)` would have slipped through. The trailing class is gone; probed with `var(--ink-dim)` in the ruleset, which now fails.

Also fixed: `scope.tsx`'s trace halo went opaque when the trace colour became an opaque hex (`shadowColor = trace`), painting a hotter glow than the espresso build it replaced. The shadow now takes an 8-digit (~55 %) form of the same hex.

Limits: no browser run, so AC4's Playwright half and AC5's page height are unverified (mitigation above). The spec's "~5.6:1" LED figure was wrong (measured 6.98:1) and is corrected. The unlit LED's `inset 0 0 0 1px rgba(0,0,0,.45)` ring is ~1.2:1 against the new panel, so the "shape, not colour" cue the spec relies on is nominally present but effectively invisible — recorded, not fixed. `--groove-accent: var(--inst-ink)` for the knob value arc is the spec's own line 20 ("knob arcs in `--inst-ink`"); `knob.tsx` was outside the declared file list and was edited only for its stale fallback.
