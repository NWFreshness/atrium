# Feature 8.2: Shared password policy

**Phase:** 8 — Integrity
**Status:** specced
**Estimated effort:** 2–3 hours
**Depends on:** 6.3
**Blocks:** nothing

## Goal

The minimum password length is 12 Unicode code points, not 12 UTF-16 code units. Signup and change-password share one policy module, so a third password surface cannot fork the rule. The 72-byte bcrypt ceiling does not change.

## Scope

Include:

- `lib/auth/password-policy.ts` — `MIN_PASSWORD_LENGTH`, `MAX_PASSWORD_BYTES`, and `checkPasswordStrength(password: unknown)` returning `{ ok: true, value: string } | { ok: false, code: "weak_password" | "password_too_long" }`
- Floor: `Array.from(value).length` (Unicode code points). `"😀".repeat(6)` is 6, not 12
- Ceiling: `Buffer.byteLength(value, "utf8") > 72` unchanged
- `signUp` / `assertPasswordStrength` and `changePassword` both call `checkPasswordStrength` and map `code` onto their own error class
- Tests for the emoji floor on both surfaces; existing ASCII 12-char and 73-byte cases still pass

Exclude (for now):

- Grapheheme-cluster counting (`Intl.Segmenter`)
- Complexity rules (digits, symbols, zxcvbn)
- Changing user-facing copy to say “code points”
- Session revocation
- 8.1 email index
- A client-side copy of the checker (the forms may keep a `minLength={12}` attribute; the server is the rule)

## Spec

1. `checkPasswordStrength`:
   - non-strings and missing values are `weak_password` (same as today’s empty-string path)
   - `Array.from(value).length < 12` → `{ ok: false, code: "weak_password" }`
   - `Buffer.byteLength(value, "utf8") > 72` → `{ ok: false, code: "password_too_long" }`
   - otherwise `{ ok: true, value }` with the original string (do not NFC-normalize)
2. The function does not throw and does not import `SignUpError` or `ChangePasswordError`. Those classes stay in their modules. Mapping:
   - signup: `weak_password` / `password_too_long` → `SignUpError(code)`
   - change-password: same codes → `ChangePasswordError(code)`, and only after current-password verification and the `unchanged` check, as today
3. `"😀".repeat(6)` is weak. `"😀".repeat(12)` is 12 code points and 48 bytes — accepted. `"abcdefghijkl"` is accepted. A string of 73 ASCII bytes is `password_too_long`.
4. `MIN_PASSWORD_LENGTH` is 12 and `MAX_PASSWORD_BYTES` is 72, defined once in the policy module. `signup.ts` may re-export them. `change-password.ts` must not duplicate the numbers.
5. Change-password still reports `wrong_current` before judging `next`, and `unchanged` before length. A six-emoji `next` with a wrong current password is still `wrong_current`.
6. No new env vars. No copy change required; “at least 12 characters” remains true for BMP text.

## Implementation notes

- Do not import the policy module from a client component. Messages modules stay copy-only. The forms already round-trip to the server action.
- `Array.from(string)` / `[...string]` splits on UTF-16 surrogate pairs, i.e. code points. That is the 6.3 follow-up. Do not add `Intl.Segmenter`.
- Keep `assertPasswordStrength` as a one-liner wrapper so signup tests that call it directly still compile.
- Do not run prettier on a directory.
