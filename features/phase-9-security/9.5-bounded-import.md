# Feature 9.5: Bounded Rolodex import

**Phase:** 9 — Security
**Status:** specced
**Estimated effort:** 2–3 hours
**Depends on:** 8.3
**Blocks:** nothing

## Goal

A CSV or vCard paste cannot be arbitrarily large. The parser and `applyImport` refuse over-size input with the existing error slot, so an authenticated member cannot turn one server action into an unbounded `createPerson` loop.

## Scope

Include:

- Constants next to the parser (not in the dialog): `MAX_IMPORT_CHARS = 1_000_000`, `MAX_IMPORT_ROWS = 500`, plus per-field ceilings (`name`/`email`/`phone`/`jobTitle`/`company`/`city`/`birthday` = 500; `notes` = 8_000)
- `parseCSV` / `parseVcf` / `applyImport` reject over those caps
- `parseImportForSession` maps the reject to `error: "That file is too large."` and empty `people`
- `applyImportAction` / `applyImport` refuse a `people` array longer than `MAX_IMPORT_ROWS` (the client can skip the parse path)
- Tests for each cap; 8.3’s catalog test still passes (the catalog module stays data-only)

Exclude (for now):

- Streaming parse, a worker, a blob store
- Changing `PERSON_FIELDS` keys
- Photo / file upload
- Throttling import POSTs per tenant (9.4 is auth-only)
- New dialog copy beyond the error string the dialog already renders from `error`

## Files to create

- None required if constants live in `lib/rolodex/import.ts`. A `lib/rolodex/import-limits.ts` is allowed if it has **no** value imports (same 8.3 rule) so the dialog *may* read the numbers later — the dialog is not required to in this feature

## Files to modify

- `lib/rolodex/import.ts` — enforce caps
- `lib/rolodex/import.test.ts` (or whatever the import tests are named) — oversize text, 501 rows, oversize notes
- `lib/rolodex/import-actions.ts` — map the error; do not parse after the char cap

## Spec

1. If `text.length > MAX_IMPORT_CHARS`, do not call Papa or `vcf`. Return/throw a typed error the action maps to `"That file is too large."`
2. If parsed people (after mapping / vcf) would exceed `MAX_IMPORT_ROWS`, same error. Do not import the first 500 and drop the rest silently.
3. `applyImport(tenantId, people)` if `people.length > MAX_IMPORT_ROWS` throws that same error **before** `listPeople`. No partial writes.
4. Each `ParsedPerson` string field longer than its ceiling is treated as a skip/invalid row (count toward `skipped`), not a truncated write. Do not slice-and-store.
5. `MAX_IMPORT_CHARS` is `string.length` (UTF-16 units). That matches `textarea.value.length` in the browser. Do not switch to byteLength here — this is a memory cap, not bcrypt.
6. The dialog still only sends `text` + `filename` to the action. Do not import Papa into the client.
7. Error copy is exactly `That file is too large.` so the dialog does not grow a second string.

## Acceptance criteria

1. [ ] `MAX_IMPORT_CHARS` is 1_000_000 and `MAX_IMPORT_ROWS` is 500, defined once
2. [ ] A 1_000_001-character string does not invoke Papa (spy or a parse-error before headers)
3. [ ] 501 valid people in `applyImport` throw/return the too-large error and insert 0
4. [ ] A notes field of 8001 characters is skipped, not stored truncated
5. [ ] `parseImportForSession` surfaces `error: "That file is too large."`
6. [ ] `lib/rolodex/person-fields.ts` still has no value imports; `lib/client-boundary.test.ts` still passes
7. [ ] `env -u DATABASE_URL npm test` and `AUTH_SECRET=ci-build-placeholder npm run build` pass
8. [ ] No new dependencies
