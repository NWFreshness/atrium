# Feature 9.2: Browser isolation headers

**Phase:** 9 — Security
**Status:** specced
**Estimated effort:** 1–2 hours
**Depends on:** nothing
**Blocks:** nothing

## Goal

Every HTML response tells the browser: do not sniff MIME, do not embed this app in a foreign frame, do not leak full URLs as referrers, do not turn on camera/mic/geo. Clickjacking and MIME-sniff are closed without a `script-src` CSP that would break Next or the theme init script.

## Scope

Include:

- `headers()` in `next.config.ts` for source `/:path*`
- A unit test that reads the config (or a tiny exported `SECURITY_HEADERS` list the config uses) and asserts the exact header names and values
- HSTS on the same list (`max-age=31536000; includeSubDomains`). Vercel HTTPS terminates at the edge; sending the header from the app is still correct for a direct Node `next start`

Exclude (for now):

- `Content-Security-Policy` `script-src` / `style-src` / nonce middleware
- Renaming `middleware.ts` to `proxy`
- Changing Auth.js cookie names or `secure` / `sameSite` (defaults are already HttpOnly + lax + Secure in production)
- 9.1, 9.3–9.6
- A Playwright header walk (the config test is the gate; `npm test` cannot see a live `next start` without the e2e secrets)

## Files to create

- `next.config.test.ts` — or colocate the assertions next to an exported header list; one file, Vitest

## Files to modify

- `next.config.ts` — `headers()` returning the list. Keep `allowedDevOrigins: ["127.0.0.1"]`

## Spec

1. Export a `SECURITY_HEADERS` array (name/value pairs) from `next.config.ts` or a tiny `lib/security/headers.ts` that `next.config.ts` imports. Next config may import that module; do not import `lib/db`.
2. The list is exactly:

   | Name | Value |
   | --- | --- |
   | `X-Content-Type-Options` | `nosniff` |
   | `Referrer-Policy` | `strict-origin-when-cross-origin` |
   | `X-Frame-Options` | `DENY` |
   | `Content-Security-Policy` | `frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'` |
   | `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` |
   | `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` |

3. `headers()` returns `[{ source: "/:path*", headers: SECURITY_HEADERS mapped to { key, value } }]`.
4. The CSP value does **not** contain `script-src`. A test asserts that, so a later drive-by cannot add `'unsafe-inline'` and call it a CSP.
5. `allowedDevOrigins` is unchanged.
6. Do not edit `middleware.ts`.

## Acceptance criteria

1. [ ] `next.config.ts` `headers()` covers `/:path*` with the six headers above, exact values
2. [ ] A test fails if `script-src` appears in the CSP value, or if `X-Frame-Options` is missing
3. [ ] `middleware.ts` is byte-identical to `main`
4. [ ] `env -u DATABASE_URL npm test` and `AUTH_SECRET=ci-build-placeholder npm run build` pass
5. [ ] No new runtime dependencies

## Implementation notes

- Next’s `headers()` `key`/`value` shape is not `{ name }` — match neighbouring Next 16 types (`NextConfig["headers"]`).
- `THEME_INIT_SCRIPT` stays an inline `<script>` in `app/layout.tsx`. That is why `script-src` is out.
- Do not run prettier on a directory.
