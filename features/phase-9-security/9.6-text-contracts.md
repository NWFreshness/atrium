# Feature 9.6: Text ceilings and LIKE escape

**Phase:** 9 — Security
**Status:** specced
**Estimated effort:** 3–4 hours
**Depends on:** nothing
**Blocks:** nothing

## Goal

Stored free text has an application ceiling, so a member cannot write multi-megabyte notes or Space blocks. Search treats `%` and `_` as literals, so a query of `%` is not “return every row.”

## Scope

Include:

- `lib/input/text.ts` — `MAX_SHORT_TEXT = 500`, `MAX_LONG_TEXT = 8_000`, `MAX_BLOCK_TEXT = 20_000`, `assertText(value, max)`, `escapeIlike(term)`
- Query barrels (CRM / Space / Rolodex) call `assertText` when they build a row, before memory/Drizzle dispatch, so both stores share the rule
- Drizzle search helpers that today do `` `%${term}%` `` wrap `escapeIlike(term)` instead
- Memory-side search predicates use the same escaped/literal behaviour (indexOf / includes on the raw term is already literal — do not start interpreting `%` in memory)
- Tests for oversize reject, exact-at-limit accept, `escapeIlike` of `\`, `%`, `_`

Exclude (for now):

- Changing column types from `text` to `varchar(n)` (a migration on every app table is out of proportion; the helper is the contract)
- HTML sanitization / markdown (React already encodes; no `dangerouslySetInnerHTML` of user content except the constant theme script)
- 9.5 import caps (already the import feature)
- A tenant-predicate SQL grep

## Files to create

- `lib/input/text.ts`
- `lib/input/text.test.ts`

## Files to modify

- `lib/crm/queries.ts` — `assertText` on create/update string fields (name, website, industry, jobTitle, email, notes/description as long)
- `lib/space/queries.ts` — page title short; block text long/`MAX_BLOCK_TEXT`
- `lib/rolodex/queries.ts` — person name short; notes long; other person strings short
- `lib/crm/queries-drizzle.ts` (and Space/Rolodex search SQL if they `ilike` with a interpolated `%term%`) — `escapeIlike`
- Matching `queries.test.ts` files — one oversize case per app is enough if the helper is unit-tested; add a CRM search case that a name containing `%` is found by `q=%` and a different org is not

## Spec

1. `assertText(value, max)`:
   - `null` / `undefined` stay nullish (optional fields)
   - non-strings throw `new Error("invalid text")`
   - `value.length > max` throws `new Error("text too long")`
   - otherwise returns `value` unchanged (no trim here — callers already trim where the product trims)
2. Short fields (names, emails, phones, titles, urls, city): `MAX_SHORT_TEXT`. Long fields (CRM activity description, Rolodex notes): `MAX_LONG_TEXT`. Space `blocks` payload text: `MAX_BLOCK_TEXT`.
3. `escapeIlike(term)`: escape `\`, then `%`, then `_`, so Postgres `ILIKE` with `ESCAPE '\'` (or the equivalent drizzle `ilike` + escaped pattern) treats them as literals. Document the ESCAPE clause in a comment; if drizzle’s `ilike` has no escape argument, use `sql\`...\`` with a bound pattern **and** `escape '\'`.
4. Search term still goes through the existing `organizationSearchTerm` (or equivalent) empty-check; escape after that.
5. Do not add `assertText` inside drizzle modules only — a memory-repo test must feel the ceiling.
6. Existing seed data must still insert (demo names are short). If a seed string exceeds a ceiling, the ceiling is wrong — raise the constant, do not shrink the seed.

## Implementation notes

- The three barrels are the 7.4 shape: guard + row construction + dispatch. Put `assertText` next to row construction, not in `queries-drizzle.ts` alone.
- Vitest has no `@/` unless `vitest.config.ts` already aliases it — copy neighbouring `lib/crm` test imports.
- Do not run prettier on a directory. Do not reflow schema files.
- If Space block payload is JSON, cap the `text` field inside the payload, not `JSON.stringify` length, unless stringify is what you store — read `createBlock` first.
