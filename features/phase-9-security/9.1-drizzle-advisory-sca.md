# Feature 9.1: Patch drizzle-orm and gate production HIGH

**Phase:** 9 — Security
**Status:** specced
**Estimated effort:** 1–2 hours
**Depends on:** nothing
**Blocks:** nothing (9.2–9.6 do not need the bump)

## Goal

The production lockfile does not contain drizzle-orm below 0.45.2 (GHSA-gpj5-g38j-94v9, identifier-escape). CI fails if a later production HIGH or CRITICAL appears.

## Scope

Include:

- Bump `drizzle-orm` so the installed version is `>= 0.45.2` (`package.json` `^0.45.2` or an exact pin at or above that)
- `npm install` so `package-lock.json` matches
- CI job `ci`: after `npm ci`, `npm audit --omit=dev --audit-level=high`
- A short comment on that step: `--omit=dev` is deliberate — drizzle-kit’s nested esbuild (moderate, GHSA-67mh-4wv8-2f99) is a **devDependency** and is waived because it is not in the Vercel runtime. Do not “fix” it by downgrading drizzle-kit to 0.18

Exclude (for now):

- Failing CI on moderate / low
- `npm audit --force` / unrelated major bumps
- Trivy, Semgrep, gitleaks, knip (parent design non-goal)
- 9.2–9.6
- Touching query modules “just in case” — Atrium does not call `sql.identifier()` or dynamic `.as()` on request input (verify with a grep; do not rewrite `orderBy`)

## Files to create

- None required

## Files to modify

- `package.json` — `drizzle-orm` range
- `package-lock.json` — refresh via `npm install`
- `.github/workflows/ci.yml` — audit step on the `ci` job (not `e2e`)

## Spec

1. `npm ls drizzle-orm --omit=dev` reports a version `>= 0.45.2`.
2. A source grep of `app/`, `lib/`, `components/` finds no `sql.identifier(` and no request-derived `.as(`. If the bump’s changelog requires a code change, it is a compile error — fix that, do not expand scope.
3. The `ci` job runs, in order: `npm ci` → `npm audit --omit=dev --audit-level=high` → `npm test` → `npm run build`. Audit before test so a known HIGH never hides behind a green suite.
4. `e2e` does not repeat the audit.
5. No new dependencies other than what the drizzle-orm bump pulls in.
6. Do not add `overrides` for esbuild.

## Acceptance criteria

1. [ ] Installed production `drizzle-orm` is `>= 0.45.2`
2. [ ] `.github/workflows/ci.yml` contains `npm audit --omit=dev --audit-level=high` on the `ci` job, after `npm ci` and before `npm test`
3. [ ] A comment next to that step names the drizzle-kit/esbuild waiver and that production HIGH must not be waived the same way
4. [ ] `env -u DATABASE_URL npm test` and `AUTH_SECRET=ci-build-placeholder npm run build` pass
5. [ ] `npm audit --omit=dev --audit-level=high` exits 0 on the branch

## Implementation notes

- `0.44.x` → `0.45.x` is a minor. If `npm test` or `npm run build` fail on a drizzle API change, stop and record it — do not silently stay on 0.44 with an override.
- Do not run prettier on a directory.
- The advisory is identifier escaping, not bound `ilike` values. Do not “harden” `orderBy` in this feature.
