# Feature 5.6: Groove Worldroom pass

**Phase:** 5 — Workroom (redesign)
**Status:** pending
**Estimated effort:** 4–7 hours
**Depends on:** 5.2
**Blocks:** 5.7

## Goal

The Groove desk becomes a proper instrument panel in the Workroom style — but stays instrument-dark in both themes, and keeps every real unit, patch, and control name from Phase 4 so no test or the domain breaks.

## Scope

Include (re-theme only, per `groove.html` and `assets/screens.css`):

- **Chassis**: a bordered, rounded "hardware" shell around the whole desk with corner `screw` marks; espresso/panel surfaces at instrument contrast (stays dark even when `data-theme="light"`), a `nameplate` ("Groovebox G-4") in mono/letter-spaced caps
- **Transport**: the `PLAY`/`STOP` button styled as a large play control with the live LED; the tempo readout (`num` + `BPM`) in Fraunces/mono with the shift-fine stepper
- **Four real units** (`unit.tsx`): RHYTHM DR-16, BASS MB-1, PADS PX-4, LEAD LX-2 — keep the exact `UNIT_META` names and the `role="region"` semantics; knob dials, drum/note grids, velocity lane, and MUTE/SOLO strip dressed as hardware
- **Master strip** (`master.tsx`): the hero FILTER knob, sweep-steps meter, the oscilloscope canvas, and the VU level tubes dressed for the panel; keep the 4.6 filter/scope wiring
- Keep the Web Audio engine untouched; no change to the real patch names (NEON RIVIERA / BASALT / SUNROOM / LATE ORBIT) or the A/B/C/D transport buttons

Exclude (for now):

- Renaming any unit or patch to the prototype's simplified labels (Drum/Bass/Keys/Lead, BOOM BAP/HOUSE/LATIN/DUB) — the prototype's `groove.html` is a visual-only stand-in for a smaller mock; the real product keeps the Phase 4 names and the sequencer/engine behaviour. Renaming would break `e2e/groove.spec.ts`, the 4.3–4.7 unit tests, and the Groove domain.
- Any engine, scheduling, audition, or `applyParams` change (Phases 4.5–4.7 are frozen)
- Restyling CRM / Space / Rolodex (5.3–5.5)
- Adding an audio-graph introspection hook

## Files to modify

- `components/groove/groove-shell.module.css` (+ `groove-shell.tsx` chassis), `transport.tsx`, `unit.tsx`, `master.tsx`, `scope.tsx` (and their module CSS)
- Only `groove-` prefixed CSS; import only from Groove files

## Spec

1. The chassis is a `role="group"`/`aria-label` "Groovebox G-4" wrapper around the existing desk; corner screws are decorative `aria-hidden`.
2. Unit `nameplate`s use the real names and unit summaries from `UNIT_META`; each unit stays `role="region"` with its unique aria-labels (KICK step 3, etc.) so the 4.3/4.8 selectors still resolve.
3. Keep the playhead-LED clock proof intact — the recomputed playhead class is a *visual* treatment; do not alter the accumulation logic the smoke asserts.
4. Groove surfaces use their own dark token set (instrument-dark), independent of the shared `light = paper` override, matching the 4.6 design note "panel can stay dark; define `[data-theme="light"]`". Reuse `--brass`/`--font-display`/`--font-mono` from 5.1 for accents and readouts.
5. MUTE still toggles a muted class; the transport still starts/stops the real engine; the scope still draws the analyser — this feature changes pixels only.

## Acceptance criteria

1. [ ] Desk renders as a chassis with screws, nameplate, transport, four named units, and the master strip in the Workroom instrument style
2. [ ] Unit/region labels and step aria-labels unchanged; `e2e/groove.spec.ts` (drum toggle, BPM copy, MUTE class, playhead accumulation) still passes
3. [ ] Groove stays dark under `data-theme="light"` while the rest of the app goes paper
4. [ ] Master strip (filter knob, sweep steps, scope, VU) styled; scope still draws the analyser while playing
5. [ ] `npm test`, `npm run build` pass; manual Chromium walk as demo (PLAY → steps accumulate → STOP) with zero console errors

## Implementation notes

- Read `groove.html` for the visual (screws, nameplate, transport, dials, sweep steps, VU) but apply it to the **real** 4.x components, using `UNIT_META` names and the live engine — do not reuse its simplified unit/patch labels.
- Some `screens.css` classes (.chassis, .screw, .nameplate, .vu, .tube, .dial, .knob) are worth porting under `groove-`-prefixed names.
