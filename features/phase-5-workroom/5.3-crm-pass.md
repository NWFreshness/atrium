# Feature 5.3: CRM Worldroom pass

**Phase:** 5 — Workroom (redesign)
**Status:** pending
**Estimated effort:** 4–6 hours
**Depends on:** 5.2
**Blocks:** 5.7

## Goal

Every CRM screen — dashboard, organizations, contacts, deals, pipeline — re-skinned with the Workroom shared classes and the warm data palette. Behaviour, TanStack tables, recharts plots, and drag-and-drop are untouched.

## Scope

Include:

- **Dashboard** (`/crm`) per `crm.html`:
  - `pagetitle` (Fraunces h1 + mono sub) and the SVG-glyph `subnav` from the `atrium-` shared classes
  - KPI row: five tiles (open deals, pipeline value, expected revenue, deals won, revenue won) with the top brass/slate/moss accent rule, Fraunces figures, mono sub — staggered `reveal`
  - Revenue & deal volume chart: recharts area/line re-themed to `--slate`/`--brass` (glowing brass), warm gridlines, mono axis labels
  - Pipeline funnel: horizontal bars per stage, warm fill widths and stage amounts
  - Win rate: the written empty state ("No closed deals yet …") in the panel when there are no closed deals
  - Top organizations: per-org bars by pipeline value
- **Tables** (organizations / contacts / deals): the TanStack tables, add/edit dialogs, and confirm-delete adopt the `--panel`/`--card`, `--field`, `--btn`, `--chip`, and `--avatar` shared styles; stage/probability chips in the data palette
- **Pipeline board**: the `@hello-pangea/dnd` six columns keep drag behaviour; column surfaces, deal cards, and probability reads get the warm mapping
- **Activity / follow-ups** rows and the recent-activity list on the dashboard dressed with the shared list/card treatments

Exclude (for now):

- Any data, query, or state change; all `crm-` helpers and TanStack/recharts requirements from phases 1.x stay
- Restyling Space / Rolodex / Groove (5.4–5.6)
- Renaming any `crm-` CSS module or class

## Files to create

- None beyond module-level CSS edits (or a per-screen override file if a screen needs bespoke workroom rules)

## Files to modify

- `components/crm/crm-subnav.module.css` (+ subnav icons in `crm-subnav.tsx`)
- `components/crm/dashboard.module.css` (+ `dashboard`/`dashboard-charts` test-friendly markup — keep `isAnimationActive={false}` and the lib aggregation split)
- `components/crm/org.module.css`, `pipeline-board.module.css` and the CRM table/dialog/activity components' CSS

## Spec

1. Dashboard aggregates stay in the `lib/crm` dashboard helpers exactly as in 1.8; the chart component must not do its own aggregation (source-grep still enforces this).
2. Recharts uses warm colors from the tokens (`var(--brass)` etc.) and keeps `isAnimationActive={false}` for the today-style charts where 1.8 set it.
3. Empty panels keep their written empty states even when counts are 0 — do not collapse them.
4. All new rules are added inside the `crm-` module (or the `atrium-` shared layer); never add shared rules inside `crm-` classes that other apps interpolate.
5. `crm-` CSS files are imported only from CRM files (per AGENTS.md), so pull shared button/card/field styles from `atrium-` rather than duplicating them in `crm-`.

## Acceptance criteria

1. [ ] Dashboard shows the five KPI tiles, chart, funnel, win-rate empty state, and top-orgs bars styled to the prototype `crm.html`
2. [ ] All CRM tables/dialogs/boards/detail pages use the shared panel/card/field/chip/avatar treatments
3. [ ] Recharts plots render warm palette and keep `isAnimationActive={false}`; aggregation still lives in `lib` (source-grep)
4. [ ] Dashboard KPI values match seed data (4 open deals, $130,000 pipeline, $66,500 expected) exactly as the prototype mocks
5. [ ] `npm test`, `npm run build`, and `e2e/crm.spec.ts` still pass; no console errors on `/crm`, `/crm/organizations`, `/crm/contacts`, `/crm/deals`, `/crm/pipeline`
