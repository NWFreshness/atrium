# Feature 5.4: Space Worldroom pass

**Phase:** 5 — Workroom (redesign)
**Status:** pending
**Estimated effort:** 4–6 hours
**Depends on:** 5.2
**Blocks:** 5.7

## Goal

Space — the sidebar tree, block editor, and database/table/board/list views — re-skinned with the Workroom direction, replacing the placeholder emoji glyphs in the page tree with inline SVG markers.

## Scope

Include:

- **Sidebar** (`space-shell.module.css`) per `space.html`:
  - `Pages` label + `⌘K` hint, quick-find input, "New page" / "New db" buttons side by side
  - Page tree rows with inline SVG glyphs (document/page, database, inbox/stack) instead of emoji; twist chevron; hover row-actions (Rename/Delete), and the footer count line
- **Block editor** (`editor.module.css`, `space-[id]` page):
  - `doc-title` with `dragdots` grab handle + Fraunces title, `doc-meta` mono updated line
  - Per-block chrome: `dragdots`, block surfaces, slash-menu trigger under the existing `/` behaviour, todo checkbox, "Click to add a block — text, list, divider, database…" affordance at the end, mini HTML tables rendered in the token style
  - Keep `@hello-pangea/dnd` drag reorder, autosave, and the vanilla per-block textareas
- **Databases** (`database-table.module.css`, `board-view.module.css`, `database-views.module.css`, `list-view.tsx`): the TanStack table, board (dnd-kit), list, filters, and sort controls dressed with the shared chip/panel/field treatments; the grouping-select on board views keeps working

Exclude (for now):

- Any page/block/row data or editing behaviour change; all `space-` helpers stay
- Restyling CRM / Rolodex / Groove (5.3, 5.5, 5.6)
- Renaming any `space-` CSS module/class or removing the permission/tenant scoping

## Files to modify

- `components/space/space-shell.module.css` + `space-shell.tsx` (and `sidebar-tree.tsx` glyphs)
- `components/space/editor.module.css` + `editor.tsx` + `slash-menu.tsx`
- `components/space/database-table.module.css`, `board-view.module.css`, `database-views.module.css`, `list-view.tsx`, `property-editors.tsx`

## Spec

1. Replace emoji tree icons with inline-stroke SVG components (document = bent page, database = cylinder, etc.) matching `space.html`; keep the accessible labels Playwright uses (`Home`, `Workroom docs`, `Product decisions`).
2. The quick-find input still opens the existing `/` + `⌘K` search (2.7); `quick-find.module.css` stays functional — restyle only.
3. The block editor keeps its per-block textarea editing and slash menu; only surfaces change. Do not introduce TipTap/ProseMirror (the 2.4 spec's "no extra editor library" rule still holds).
4. Database views keep TanStack Table and dnd-kit as named in 2.5/2.6; this feature only re-skins them.
5. New rules join the `space-` module (or `atrium-` shared layer); shared button/card/field styles come from `atrium-`, not duplicated `space-`.

## Acceptance criteria

1. [ ] Sidebar renders the Pages header, quick-find, New page/New db buttons, SVG-glyph tree, hover row-actions, and footer count
2. [ ] Editor page shows the dragdot title, mono meta, per-block dragdots, add-block affordance, and token-styled mini-tables
3. [ ] No emoji icons remain in the Space tree (source-grep)
4. [ ] Create/rename/delete page, block editing, autosave, drag reorder, and database view switching all still work via `e2e/space.spec.ts` and the 2.x unit tests
5. [ ] `npm test`, `npm run build` pass; no console errors on `/space`

## Implementation notes

- In `space.html` the tree mixes page, folder, and database nodes (cylinder for the database, bent page for documents, inbox for the Inbox) — map each existing node `icon`/`kind` to its inline glyph.
- The prototype's database notation differs from the shipped 2.5 defaults only in chrome; preserve the seeded data, don't renumber.
