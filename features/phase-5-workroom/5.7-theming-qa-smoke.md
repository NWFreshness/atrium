# Feature 5.7: Theming QA + smoke

**Phase:** 5 — Workroom (redesign)
**Status:** pending
**Estimated effort:** 3–4 hours
**Depends on:** 5.3, 5.4, 5.5, 5.6
**Blocks:** nothing

## Goal

Prove the redesign is coherent: the Workroom look holds across both themes and all four apps, per-app CSS namespaces are intact, no console errors appear anywhere, and the redesign did not regress any existing feature.

## Scope

Include:

- A consistency pass across dark and light: each surface/ink/accent uses the tokens; no leftover flat-black/blue accent; light is paper, Groove stays dark; the `atrium.theme` toggle still re-themes the whole product and survives reload
- Source-grep QA asserting the CSS namespace rule: `crm-`/`space-`/`rolodex-`/`groove-` module files are imported only from their own app's components, and shared `atrium-*` classes are not reimplemented ad hoc inside per-app modules
- Playwright:
  - Unauth `/` → `/login`; login themed
  - Launcher shows four described app cards in Workroom style; navigate each
  - Both themes render warm values (assert the computed body background is *not* flat black in dark and is paper in light); theme survives reload
  - Walking launcher + `/crm*` + `/space` + `/rolodex*` + `/groove` logs zero console errors
  - Groove desk renders chassis + four named units + master strip, and stays dark under `data-theme="light"`
- Full-suite regression: every prior Playwright spec (login, launcher/theme, CRM, Space, Rolodex, Groove) stays green

Exclude (for now):

- Screenshot visual-diff baselining / goldens (deferred; not a v1 block)
- New product features or copy beyond what 5.1–5.6 defined
- Re-litigating the palette — this is the QA gate, not the design authority (the design doc is)

## Spec

1. The no-console-error walk is the central gate: a demo (or owner) login, then visit `/` (launcher), `/crm`, `/crm/organizations`, `/crm/contacts`, `/crm/deals`, `/crm/pipeline`, `/space` (and an existing page id from a `listPages`-style read), `/rolodex`, `/rolodex/people`, `/rolodex/circles`, `/rolodex/calendar`, `/rolodex/timeline`, `/groove`; collect `pageerror`/`console.error` and fail on any.
2. Theme assertion: read `document.documentElement.getAttribute("data-theme")` and the `getComputedStyle(document.body).backgroundColor`; dark must be the espresso family (not `#000`/near-black with no grain), light must be paper. Toggle, assert, reload, assert persisted (`atrium.theme`).
3. Namespace grep mirrors the existing source-grep conventions: for each app, its `*.module.css` files are imported (referenced by `import ... from ...module.css`) only inside that app's own component/layout files.
4. This feature closes Phase 5; its acceptance criteria all must hold locally with `.env` secrets and be re-run by the controller (`npm test` + `AUTH_SECRET=ci-build-placeholder npm run build` + full `npx playwright test`).
