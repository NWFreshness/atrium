# Feature 5.2: Shared chrome, launcher, and login

**Phase:** 5 — Workroom (redesign)
**Status:** pending
**Estimated effort:** 4–6 hours
**Depends on:** 5.1
**Blocks:** 5.3, 5.4, 5.5, 5.6

## Goal

The shared surfaces — top nav, launcher, and login — adopt the Workroom direction, and the shared presentational classes every app pass will reuse land here.

## Scope

Include:

- **Top nav** (`atrium-nav-` prefixed, per AGENTS.md) redesigned per `index.html`/`crm.html`:
  - Brand: brass diamond mark (`brand .mark`) + "Atrium" in Fraunces
  - Nav glyphs: the four inline SVG icons from the prototype (CRM diamond, Space cylinder, Rolodex person, Groove machine) instead of the current text/emoji treatment
  - Brass active link + top/bottom brass underline sweep on hover and active; dim ink idle
  - Identity chip: avatar badge (initial in a brass ring) + email; theme toggle; Reset demo and Logout as surfaced `atrium-nav-` buttons
  - Sticky, translucent-lifted surface (`backdrop-filter`) instead of opaque flat
- **Launcher** (`/`): four described app cards (`.appcard`) per `index.html` — per-app SVG icon, title, one-line description, "Open →", brass-on-hover lift + `--app-glow` colored edge, staggered `reveal`
- **Login** (`/login`): the oversized brass "A" watermark, brand row + Fraunces "Atrium", tagline "Four personal apps, one login.", and the card with the two-field form and the `btn-primary` Sign in, per `login.html`
- **Shared presentational classes** (from the prototype `workroom.css`, `atrium-` prefixed so they are safe across apps): button (`btn`/`btn-primary`), field/input, panel/card, `label` small-caps, `chip` (with `--chip-c` color), `avatar` (initial, `--av` color), `kpi` (top accent rule + Fraunces figure), `subnav`/`subtab` (brass active underline), `pagetitle` (Fraunces `h1` + mono `sub`)

Exclude (for now):

- Per-app content restyle beyond the shared classes (5.3–5.6)
- Groove chassis / master (5.6)
- Any behaviour or copy change outside chrome (login flow, logout, reset, theme toggle all keep their existing handlers)

## Files to create

- `app/workroom/chrome.css` (or `components/atrium-shared.module.css`) — the `atrium-` prefixed shared class set
- Optional: `components/atrium-*.tsx` for the avatom badge / glyph icon wrapper if the current nav component is too tangled

## Files to modify

- `components/atrium-nav.tsx` + `components/atrium-nav.module.css` — redesigned top nav
- `app/(authenticated)/page.tsx` — launcher cards
- `app/login/login-form.tsx` / `app/login/page.tsx` (+ its CSS) — login card
- `app/globals.css` — only to reference the shared layer from the right scope (keep `atrium-shared` and `atrium-nav` self-contained)

## Spec

1. Port the nav visual from the prototype but keep the semantics and handlers of the current `atrium-nav.tsx` (Home + four apps, current brass, email identity, theme toggle, Reset demo when `role === demo`, Logout). Replace the hidden nav with an accessible one: brand is a landmark link, each app link has its label text (keep the real names "Home / CRM / Space / Rolodex / Groove" for the Playwright `getByRole(name, { exact: true })` smokes).
2. SVG glyph icons are inline components, not an icon font; stroked `currentColor`, `stroke-linecap: round`.
3. Launcher cards are `role="link"` anchors to each app route; the four descriptions copy the prototype wording.
4. Login keeps the existing server action (`login/actions.ts`) — only the visual changes. The form fields keep their `name`/`autocomplete` attributes.
5. Shared `atrium-` classes are inert (no feature behaviour) — they exist so 5.3–5.6 style with tokens and don't redeclare buttons/cards.

## Acceptance criteria

1. [ ] Top nav renders the brand mark, four SVG-glyph app links, identity chip, and controls in the Workroom style; active app is brass with the underline sweep
2. [ ] Launcher shows four described cards with the staggered reveal; each navigates to its app
3. [ ] Login renders the brass "A" watermark, brand row, tagline, and `btn-primary` Sign in; existing `AUTH_OWNER`/`AUTH_DEMO` login still works and errors still show the generic message
4. [ ] `atrium-` shared classes present and used by nav/login/launcher; `atrium-nav-` prefix rule still satisfied
5. [ ] `npm test`, `npm run build`, and the full Playwright suite (login, launcher, theme, all app smokes) pass
