# Feature 5.1: Design system + theme scaffold

**Phase:** 5 — Workroom (redesign)
**Status:** pending
**Estimated effort:** 3–5 hours
**Depends on:** nothing
**Blocks:** 5.2, 5.3, 5.4, 5.5, 5.6, 5.7

## Goal

The foundation of the Workroom: design tokens, the Fraunces + Geist Mono type stack, and the global theme scaffold (espresso dark default, warm "paper" light) land in the app so every later per-app pass can consume them. No screen is restyled yet.

## Scope

Include:

- CSS custom-property tokens, defined once at the document root, matching the prototype `assets/workroom.css` values:
  - Surfaces (dark): `--bg-0 #13100c`, `--bg-1 #1b1712`, `--bg-2 #231e16`, `--bg-3 #2b251b`; `--line #312a1f`, `--line-strong #463c2a`
  - Ink (warm): `--ink #f0e9da`, `--ink-dim #a99e88`, `--ink-faint #7a6f5b`
  - Brass accent: `--brass #dfa33c`, `--brass-bright #f2bd63`, `--brass-deep #8a5f1e`, `--brass-soft`, `--brass-glow`
  - Data palette (warm-shifted): `--moss #8fae83`, `--clay #cd7258`, `--slate #8b9fc2`, `--violet #a88fc0`, plus `--good`/`--warn`/`--bad` aliases
  - Type: `--font-display` Fraunces, `--font-sans` Geist, `--font-mono` Geist Mono
  - Geometry: `--r-sm/md/lg`, `--shadow-panel`, `--glow-brass`
- `[data-theme="light"]` overrides = warm paper (`#ece5d6` → `#fffdf6` surfaces, `#262015` ink, deep brass `#a86f14`), matching the prototype's light block
- `<html>`/`<body>` adopt surfaces + ink; `color-scheme: dark` / `light`
- Low-opacity SVG paper-grain overlay (`body::before`) and top radial brass glow (`body::after`); `z-index` keeps both below interaction
- Text selection in `--brass-soft`
- Fraunces and Geist Mono loaded (via `next/font` or the Google stylesheet the prototype lists), with Geist joining the stack
- Motion primitives for later passes: a `reveal` stagger (<code>opacity/translateY</code> keyframed, `--i` step index) and a `@media (prefers-reduced-motion: reduce)` guard that disables it

Exclude (for now):

- Restyling any app screen (5.3–5.6), the top nav or launcher (5.2)
- Editing existing CSS modules (`crm-`/`space-`/`rolodex-`/`groove-`) or `atrium-nav-`
- Removing the existing amber theme or renaming `atrium.theme`
- Any database, domain, or behaviour change

## Files to create

- `app/theme-tokens.css` (or tokens in `app/globals.css` — one place, no duplication)

## Files to modify

- `app/globals.css` — token block, light overrides, body surfaces, grain + glow overlays, selection, reveal + reduced-motion
- `app/layout.tsx` — font wiring (Fraunces, Geist Mono); keep the existing pre-paint `data-theme` init script

## Spec

1. Port the token values verbatim from the prototype's `:root` and `[data-theme="light"]` blocks into the app's global CSS as CSS custom properties.
2. The light theme is a warm "paper" recolor of the same palette — not a white or grey theme. `--brass`, ink, and data colors each get a light-theme variant.
3. App HTML/body uses the tokens (`background: var(--bg-0)`, `color: var(--ink)`, `font-family: var(--font-sans)`), replacing the current flat-black default so the shape of the new theme is visible immediately.
4. Add the two overlays as fixed, pointer-events-`none`, `z-index: 0`/`60` layers so no interaction is blocked; opacity is low enough to read as texture, not noise.
5. The `reveal` animation uses a `--i` integer step index (70 ms stagger) so later passes can drop it on page/rows for the staggered load. `prefers-reduced-motion` disables it and collapses transition durations.
6. Do not touch any CSS module. The foundation must compile clean against the current per-app styles.
