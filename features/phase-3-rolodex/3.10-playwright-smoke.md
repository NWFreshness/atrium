## Goal

CI can prove a logged-in demo user can walk Rolodex without 404s or mixed-tenant data.

## Scope

Include:

- `e2e/rolodex.spec.ts`
- Unauthenticated `/rolodex` → `/login`
- Demo login → `/rolodex` Today renders; five subnav sections open
- People table shows seed names
- One write path: create or edit a person (or log an interaction) and still see it after reload
- Owner login: Rolodex does not show demo seed names
- CI already runs `npx playwright test`; do not hardcode only `login.spec.ts`

Exclude (for now):

- Full Bench exploratory / visual walkthrough of every screen
- Visual screenshot diffs
- Groove e2e
- Mouse kanban e2e unless already cheap (unit tests cover move)

## Implementation notes

- Use `AUTH_DEMO_*` for the happy path; skip if missing (same pattern as demo login test).
- Prefer role/label selectors over brittle CSS.
- Login uses owner/demo email and password. `AUTH_SECRET` is JWT signing — if next logs `MissingSecret`, run e2e with `AUTH_SECRET=...` in the **process environment for that command only**. Do not write a secret into `.env` unless asked.
- Quote paths that contain parentheses (`"app/(authenticated)/rolodex"`) in shell commands.
