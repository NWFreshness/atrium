## Goal

Rolodex tables exist, every query is tenant-scoped from the session, demo data can be seeded and wiped without touching the owner tenant. Cadence and annual-date helpers match the reference implementation.

## Scope

Include:

- Drizzle tables: `people`, `interactions`, `importantDates`, `facts`, `news`, `reminders`, `gifts`, `connections` — each with `tenantId`
- UUID text ids (match users/tenants)
- Constants: circles, cadences, interaction types, date types, gift kinds, connection kinds, check-in statuses
- Pure `computeStatus` / `cadenceDays` (port the reference implementation's `cadence.ts`) and annual-date helpers (port `importantDates.ts`: next occurrence, 29 Feb → 28 in common years, milestone when age this year ends in 0)
- Query helpers that take `tenantId` as a required argument (never from the client)
- Dual-path memory repo + Drizzle; optional filters as a trailing `opts` after `repo`
- `lastContacted` and `latestNews` computed on read (MAX interaction date; newest news). Not columns on `people`
- Demo seed for the demo tenant only; owner tenant stays empty
- `registerDemoResetter` that deletes that tenant’s Rolodex rows then re-seeds demo
- Unit tests without `DATABASE_URL`

Exclude (for now):

- Rolodex UI (3.2+)
- TanStack, drag-and-drop, charts, Papa Parse / vcf
- Photo column or upload
- Changing circle names or cadence defaults at runtime
- Groove tables

## Spec

Postgres field shapes (camelCase, like CRM). Calendar dates are ISO `YYYY-MM-DD` text. `createdAt` / `updatedAt` are timestamptz.

```ts
// people: id, tenantId, name, email, phone, jobTitle, company, city, timezone,
//   circle, cadenceOverrideDays, checkinsOff, snoozedUntil, howMet, metWhere, metOn,
//   notes, tags (jsonb string[]), createdAt, updatedAt
//   no photo
// interactions: id, tenantId, personId → people.id cascade, type, date, notes, createdAt
// importantDates: id, tenantId, personId cascade, type, label, month, day, year?, createdAt
// facts: id, tenantId, personId cascade, text, createdAt
// news: id, tenantId, personId cascade, text, date, createdAt
// reminders: id, tenantId, personId cascade, text, dueDate, done, doneAt, createdAt
// gifts: id, tenantId, personId cascade, name, kind, occasion, date, createdAt
// connections: id, tenantId, personA cascade, personB cascade, kind, aIsParent,
//   label, inverseLabel, note, createdAt
```

`tenantId` → `tenants.id` restrict.

`CIRCLE_META`: inner 30, close 91, wider 182, distant 365. `due_soon` window = 7 days.

Never contacted: next due is today → `due_soon` today, `overdue` from tomorrow.

Deleting a person cascades interactions, dates, facts, news, reminders, gifts, and connections on either side.

Demo seed: ≥30 people, no empty circle, a birthday in each of the next three months, interactions ≥1 year back, at least one of every other type. Deterministic names (port the reference implementation's seed intent, not SQLite ids). Owner: none. Idempotent skip when that tenant already has people. Reset still deletes then seeds.

## Implementation notes

- Behavior bible: the reference implementation's `docs/rolodex/` and `server/src/rolodex/`. Prefer the reference code if REQUIREMENTS and code disagree, then add `tenantId`.
- Do not re-export names containing `rolodex` from `lib/db/schema.ts` (`schema.test.ts` checks `Object.keys`).
- Import `getTableColumns` from `drizzle-orm`, not `drizzle-orm/pg-core`.
- Drizzle `getTableConfig` FK `foreignTableName` is undefined — assert `${column.name}:${onDelete}` (e.g. `personId:cascade`, `tenantId:restrict`).
- Missing-tenant seed throw must call `seedDemoRolodex`, not a copied `seedDemoCrm`.
- neon-http has no real transactions; prove reset/rollback with injected `runInTransaction`.
- After merge: `npm run db:migrate` then `npm run db:seed` against the Neon **dev** URL. Seed will not backfill an already-seeded demo tenant — Reset demo.
