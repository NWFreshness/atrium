# Feature 3.4: CSV and vCard import

**Phase:** 3 — Rolodex
**Status:** completed
**Estimated effort:** 4–5 hours
**Depends on:** 3.3
**Blocks:** nothing

## Goal

A user can import people from a CSV or vCard file: map columns, preview, skip flagged duplicates, then apply. Nobody is imported if apply fails.

## Scope

Include:

- Import entry from People (button that opens a dialog)
- Parse CSV with Papa Parse; parse `.vcf` with `vcf`
- Suggested column mapping from header synonyms (Bench `HEADER_SYNONYMS`)
- Fields: name (required), email, phone, job title, company, city, birthday, notes
- Preview of people that will be added
- Duplicate detection: email first, then exact name (case-sensitive match as Bench). Flagged rows cannot be ticked for import; others selected by default
- Apply all-or-nothing (injected transaction in tests; delete-then-insert limitation of neon-http documented if needed)
- Birthday mapping creates an `importantDates` birthday when month/day can be parsed
- Unit tests for parse, mapping, ragged CSV rows, duplicate flagging, and apply isolation
- `papaparse` and `vcf` added in this feature, not earlier

Exclude (for now):

- Export, contact sync, merge-on-import
- Photo from vCard
- Circle/tag mapping beyond notes

## Spec

Port Bench `server/src/rolodex/import.ts`:

- Ragged CSV: `Record<string, string | undefined>` — missing cells are undefined, not `""`
- vCard `propValue` handles both `valueOf()` shapes (string vs jCard tuple)
- Name required; rows without a name are skipped and counted
- Apply writes only non-duplicate selected rows in one transaction

## Acceptance criteria

1. [x] A CSV file and a vCard file can each be imported; count and content match the preview
2. [x] Suggested mapping fills Name/Email/etc. from synonym headers
3. [x] A file containing someone already in the tenant (email or exact name) flags them; they cannot be imported as a second copy
4. [x] Parse failure or apply failure imports nobody and shows a banner
5. [x] Imported people are tenant-scoped; owner and demo do not mix
6. [x] Unit tests cover parse, ragged rows, duplicates, and apply
7. [x] `npm test` and `npm run build` pass
8. [x] No regressions in 3.3
