# Feature 4.1: Groove domain (types, music, filter, params, patches)

**Phase:** 4 — Groove
**Status:** completed
**Estimated effort:** 4–5 hours
**Depends on:** 0.4
**Blocks:** 4.2, 4.3, 4.4, 4.5, 4.6, 4.7, 4.8

## Goal

Pure TypeScript for the instrument exists and is tested without Web Audio, without a database, and without UI. Factory patches are playable snapshots.

## Scope

Include:

- Types: `UnitId`, `UNIT_IDS`, `DRUM_LANES`, `DrumPattern`, `MelodicStep`, `Params`, `Patch`, `ParamSpec`, `STEPS = 16`, `SWEEP_BARS`
- `music.ts`: `noteName`, `mtof`, `CHORD_SHAPES`, `VOICINGS`, `chordIntervals`, `clampNote` / `clampIndex` (port Bench)
- `filter.ts`: DJ macro (`FILTER_OPEN = 0.5`), `lowpassHz`, `highpassHz`, `filterLabel`, `filterGainAt`
- `params.ts`: `UNIT_PARAMS`, `UNIT_META` (RHYTHM DR-16, BASS MB-1, PADS PX-4, LEAD LX-2), `FILTER_SPEC`, `MASTER_GROUPS`, `MASTER_PARAMS`
- `patches.ts`: four factory patches + `clonePatch` (port Bench `patches.ts`, including names and BPM)
- Unit tests without `DATABASE_URL` and without `AudioContext`

Exclude (for now):

- Groove UI (4.2+)
- Web Audio engine (4.5)
- Drizzle tables, seed, demo resetter
- Tone.js, samples, extra audio libraries

## Spec

Port Bench `web/src/groove/{types,music,filter,params,patches}.ts`. Prefer that code if REQUIREMENTS (three patches) disagrees — ship four.

Patches (Bench `INSTRUMENT.md` / `patches.ts`):

- A NEON RIVIERA — 112 BPM
- B BASALT — 130 BPM
- C SUNROOM — 94 BPM
- D LATE ORBIT — 126 BPM

Each patch has drums (six lanes × 16 steps, values 0|1|2), bass/pads/lead (16 `MelodicStep`s in MIDI range 24–96), and a master `Params` bag. No unit is entirely silent. `clonePatch` is a deep copy.

Filter: macro `< 0.5` lowpass, `> 0.5` highpass, centre `OPEN`. Shared by later audio, readout, and scope.
