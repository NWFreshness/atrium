# Feature 4.3: Knobs, faders, and sequencer grids

**Phase:** 4 — Groove
**Status:** completed
**Estimated effort:** 5–6 hours
**Depends on:** 4.1, 4.2
**Blocks:** 4.4

## Goal

Each unit is playable as a panel: knobs and faders from `UNIT_PARAMS`, a 16-step grid, unique accessible names. No Web Audio yet.

## Scope

Include:

- Knob (drag up/down, shift = fine) and Fader
- DrumGrid: six lanes, each step cycles rest → hit → accent
- NoteGrid: click toggles; drag/scroll changes pitch; pads shift-click cycles chord shape
- VelocityLane under melodic sequencers
- LedStrip (playhead index, `-1` when stopped)
- Unit: name/model from `UNIT_META`, param controls, sequencer, MUTE button (wired in 4.4)
- Per-cell `aria-label` (`KICK step 3`, `BASS step 12`) and `aria-pressed`
- Unit tests for grid toggle / chord cycle / label uniqueness (no AudioContext)

Exclude (for now):

- Transport play/patch/keyboard (4.4)
- Web Audio (4.5)
- Master knobs (4.6)
- Pixel-identical reference CSS

## Spec

Port the reference implementation's `web/src/groove/components/{Knob,Fader,DrumGrid,NoteGrid,VelocityLane,LedStrip,Unit}.tsx`.

`getByRole` matches names as substrings. Labels must use `exact: true` in tests so `BASS step 1` is one button, not steps 10–16.

Drum values: 0 off, 1 hit, 2 accent. Melodic `note` stays in `NOTE_MIN`–`NOTE_MAX`.

## Acceptance criteria

1. [x] Four units render knobs/faders from `UNIT_PARAMS` and a 16-step grid
2. [x] Drum step `KICK step 3` is uniquely named and cycles rest/hit/accent
3. [x] Melodic `BASS step 1`, `PADS step 1`, `LEAD step 1` each have count 1 (`exact: true`)
