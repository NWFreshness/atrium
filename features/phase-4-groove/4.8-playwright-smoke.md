# Feature 4.8: Groove Playwright smoke

**Phase:** 4 — Groove
**Status:** pending
**Estimated effort:** 3–4 hours
**Depends on:** 4.7
**Blocks:** nothing

## Goal

CI can prove a logged-in user can boot the instrument, run the sequencer, and use the main controls. Tests assert nothing about sound.

## Scope

Include:

- `e2e/groove.spec.ts`
- Unauthenticated `/groove` → `/login`
- Demo (or owner) login → four regions RHYTHM, BASS, PADS, LEAD
- Transport starts and stops; playhead leaves `-1` then returns
- Drum `KICK step 3` (`exact: true`) toggles `aria-pressed`
- Melodic `BASS step 1` / `PADS step 1` / `LEAD step 1` each count 1 (`exact: true`)
- Switching to BASALT changes the BPM copy
- RHYTHM MUTE toggles a muted class
- Running the sequencer logs no console errors
- Playhead proof: accumulate LED “on” classes (MutationObserver). Do not sample with `expect.poll` alone — Bench PROCESS: 134 ms steps alias against a 1 s poll
- At least 12 distinct steps seen in 10 s (`MIN_STEPS_SEEN`)
- CI already runs `npx playwright test`

Exclude (for now):

- Full Bench exploratory / “does it sound good”
- Visual screenshot diffs
- Audio-graph introspection hooks
- Tenant isolation of seed people (Groove has no tenant data). Owner and demo both get the instrument

## Implementation notes

- Port Bench `e2e/groove/instrument.spec.ts`, then add Atrium login like `e2e/rolodex.spec.ts`.
- Use `AUTH_DEMO_*` or owner pair; skip if missing (same pattern as other smokes).
- Login uses owner/demo email and password. `AUTH_SECRET` is JWT signing — if next logs `MissingSecret`, run e2e with `AUTH_SECRET=...` in the **process environment for that command only**.
- Prefer role/label selectors. `exact: true` on step names.
- Headed runs play sound out loud — the spec should STOP the transport in `finally` / after each test.
