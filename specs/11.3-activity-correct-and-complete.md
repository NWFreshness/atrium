# 11.3 — Activity correct-and-complete

## Phase
Phase 11 — CRM integrity sweep. Closes gaps **G1** (no activity edit/delete UI), **G7** (no backdating), and **G8** (Last contacted is derived in Rolodex but unused in CRM). The phase-11 design merges the legacy A2 (edit + delete) and B4 (backdate + last-contacted) intents into this one feature. Depends on **11.1** (e2e coverage for the activity timeline and pipeline drag), which is `passing`.

## Goal
Make the activity timeline correctable. A user can edit or delete any activity from the timeline, can backdate an activity through a new `Date` field on the form, and can see a derived **Last contacted** value on the contact detail page and the contacts table — without storing a `lastContactedAt` column anywhere in the schema.

## User-visible behavior
- Every row in the activity timeline on `/crm/contacts/[id]` and `/crm/deals/[id]` shows **Edit** and **Delete** controls that are visible at rest (no hover required). Pressing them does not require the form to scroll.
- **Edit** opens the existing `ActivityForm` as a modal dialog (heading literal `Edit activity`, `Save` / `Cancel` buttons). The form is pre-populated with the row's current `type`, `description`, `date`, and `done` state, and now exposes a `Date` field bound to `occurredAt`. `Save` persists; `Cancel` discards; `Escape` closes; focus returns to the Edit button on close. The dialog is `role="dialog" aria-modal="true" aria-labelledby={useId()}` and opens focused on the `Type` select.
- **Delete** runs `confirm("Delete this activity?")` and on OK removes the row. A reload leaves it gone.
- The `Date` field is also added to the existing inline `Add activity` form on the contact and deal detail pages. It is `type="date"`, midnight UTC, defaulting to today.
- An activity created with a past `Date` renders `formatDate(occurredAt)` in the timeline and survives a page reload.
- Editing a row's `Date` to a value later than every other activity on the page makes it the **first** `<li>` in the timeline after reload.
- The contact detail page renders a `Last contacted` row with `formatDate(value)` or the literal `No activity yet` when there is none. The contacts table renders `Never` when there is no record and `formatDate(value)` otherwise. When the most recent contact is more than 30 days old, the table cell appends ` · N days ago` and gains the `crm-stale` class. At exactly 30 days, neither the suffix nor the class is shown.
- **Last contacted is derived** from `activities` per contact via `compareActivitiesNewestFirst`. No column is added to `contacts`.
- The accessible name of every per-row control is the **truncated** activity description: `Edit activity: …`, `Delete activity: …`, `Mark activity: … done` / `Mark activity: … not done`. Truncation is `truncateActivityLabel` (60 chars + `…`).
- The dashboard feed (`app/(authenticated)/crm/page.tsx`) and the dashboard follow-up panels (`components/crm/dashboard-followups.tsx`) stay read-only and are not modified.
- No new CRM subnav tab. No new route. No toast. No undo. No re-parenting of an activity through the form. No "last contacted" filter on contacts (out of this phase).

## Out of scope
- Activity creation UI anywhere new; the inline `Add activity` form on contact and deal detail pages only gains the new `Date` field.
- Any edit/delete control on the dashboard feed or the follow-up panels. `components/crm/dashboard-followups.tsx:36-59` and `app/(authenticated)/crm/page.tsx:64-96` are **not** modified.
- `/crm/tasks`, the follow-up section, or a "See all" link. That is 11.9.
- Re-parenting an activity. Edit does not offer an Organization/Contact/Deal picker. The FKs are nullable `SET NULL`, and a mis-click would silently orphan the row.
- Undo or a toast. No toast primitive in the repo; this phase adds none.
- Time-of-day precision on `Date`. Field is `type="date"`, midnight UTC.
- A "last contacted" filter on contacts. Out of this phase.
- Deal number validation, deal filters, table sorting (as a *general* feature; 11.4 sorts other columns; the new Last contacted column is unsortable in this card), detail-page edit, delete preview, QuickFind, the unique email index. Those are 11.2, 11.4, 11.5, 11.7, 11.8, 11.10, 11.6.
- Editing `e2e/crm-pipeline.spec.ts` or any other e2e file outside the two listed.
- Rolodex strings. Cross-app copy divergence (`Never` / `No activity yet` / `Never contacted`) is recorded, not fixed.
- Linting. Lint is not a gate.

## Failure and edge cases
- **Wrong-tenant id:** both new `*ForSession` helpers return `null`. The dialog treats `null` as "row no longer exists" and closes without saving.
- **Unknown activity type at update:** `updateActivityForSession` returns `null`; the form surfaces the existing validation message and does not dispatch.
- **Stale `Last contacted`:** 30 days exact is "fresh" (no suffix, no class); 31 days exact renders the suffix and the class. Off-by-one regression is the named red in AC5.
- **Re-parenting:** the form does not expose org/contact/deal fields, so a mis-click cannot orphan a row.
- **Delete with no orphan cleanup:** the demo reset is a per-environment precondition the implementer honors before the Playwright run; the card does not re-implement it.
- **Two activities sharing a 60-character description prefix** are indistinguishable by accessible name. The visible `<p>` is the disambiguator. Recorded limit, not a defect.
- **No focus trap** in the dialog; `Escape` and the Cancel button close.
- **Date field is UTC midnight.** A user in a non-UTC timezone entering today's date sees that date rendered in the timeline; no time-of-day precision is promised.
