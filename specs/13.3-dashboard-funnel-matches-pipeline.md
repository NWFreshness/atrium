# 13.3 — Dashboard pipeline funnel matches the pipeline board

## Phase

(provisional) phase-13 — dashboard correctness follow-up. NOT in
`roadmap/phases.yaml` (phases 11–12 cover CRM integrity and deal history; no
dashboard-accuracy intent exists there). Follows 13.2 (shipped as PR #105).
This spec does not move, rename, or depend on any 11.x / 12.x intent.

## Goal

The CRM dashboard "Pipeline funnel" must agree with the pipeline board: a deal
sitting in a board column must be counted in the corresponding funnel bar. The
reported symptom is that the funnel's Won bar is empty while the board shows a
Won deal.

## User-visible behavior

- CRM dashboard (`/crm`) "Pipeline funnel": the Won bar counts every deal the
  pipeline board shows in its Won column: every deal currently in stage Won is
  counted, regardless of its `closeDate` (null, older than the trailing window,
  or inside it). The trailing-window filter no longer applies to the funnel.
- Open-stage bars (New+, Qualified+, Proposal+, Negotiation+) continue to match
  the board's open columns as today; the fix must not change their counts for
  deals that already appear.
- No other dashboard panel changes its labeled meaning: "Deals won" /
  "Revenue won" stay trailing-6-month tiles (the tile subtitles say so), unless
  Q2 extends scope.

## Scope paths

- `lib/crm/dashboard.ts` (`pipelineFunnel`, and `buildDashboard` only insofar
  as the `sinceMonth` argument changes)
- `lib/crm/dashboard.test.ts` (unit coverage for the fixed inclusion rule)

## Out of scope

- The pipeline board itself — its columns are the reference truth, not the fix
  target.
- Lost-stage handling: the funnel is Won-terminated by design (`FUNNEL_STAGES`
  has no Lost entry and Lost deals are excluded from every bar). No Lost bar,
  no change to that rule.
- DB migration, seed-data edits, or backfilling `closeDate` on old Won deals
  (unnecessary if Q1 resolves to "no date filter in the funnel").
- Styling, theming, or chart-layout changes (13.1/13.2 territory).
- `winLoss`, `monthlyRevenue`, `topOrganizations`, tiles: untouched unless Q2
  says otherwise.

## Acceptance criteria

(AC1–AC3 are final — Q1/Q2 decided via defaults on 2026-10-07.)

- AC1: a tenant with one Won deal on the board and nothing else sees Won
  count = 1 in the funnel, regardless of that deal's `closeDate` (null, older
  than 6 months, or inside the window).
- AC2: unit test in `lib/crm/dashboard.test.ts` pins the reported case: Won
  deal with a missing or out-of-window `closeDate` is counted by
  `pipelineFunnel`.
- AC3: open-stage funnel counts for existing fixtures are unchanged
  (no regression in the bars that already agree with the board).

## Failure and edge cases

- Won deal with `closeDate = null`: today `closeMonthKey(null)` returns `""`,
  which fails the `>= sinceMonth` comparison, so the deal is silently dropped
  from `live`. The fix must cover this case explicitly, not just shift the
  window.
- Won deal closed before the trailing window (e.g. last year): today it is
  dropped from the funnel while the board still shows it. Any window-keeping
  resolution must state what the funnel shows for it; a board-matching
  resolution includes it.
- Tenant scoping is unchanged: funnel input is the tenant's own deal list from
  `getDashboard`; the fix changes filtering, never the tenant boundary.
- Empty pipeline: funnel renders all-zero bars as today, no new empty-state
  strings.

## Decisions

- Q1 decided (default): the funnel mirrors the board exactly. Every deal in
  stage Won is counted; `closeDate` and the trailing window are ignored by
  `pipelineFunnel`. Rationale: the funnel is a snapshot of the current
  pipeline, and the tiles already carry the trailing-window story with
  explicit "Trailing 6 months" labels.
- Q2 decided (default): funnel only. `winLoss`, `monthlyRevenue`,
  `topOrganizations`, and the tiles keep their current windowed semantics.
- Status: `spec_ready`.

- Id `13.3` minted as provisional phase-13 (roadmap has phases 11–12 only;
  follows the 13.1/13.2 precedent). Roadmap not edited.
- Root-cause hypothesis (verified in the working tree, not assumed):
  `pipelineFunnel` (`lib/crm/dashboard.ts:131-153`) builds `live` as open
  deals plus Won deals with `closeMonthKey(closeDate) >= sinceMonth`, where
  `sinceMonth` is 5 months back (`buildDashboard`, line 246). A Won deal with
  a null `closeDate` (`"" >= sinceMonth` is false) or a pre-window `closeDate`
  is excluded from the funnel while the board (stage-grouped, no date filter)
  still shows it. Implementer must confirm against the live board before
  changing the rule.
- Funnel's cumulative-bar semantics (`New+` counts everything downstream, Won
  bar counts Won only) and Won-terminated stage list are kept; only the Won
  inclusion filter changes (Q1 resolved: date/window filter removed for Won).
